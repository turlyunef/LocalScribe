# Подключение ASR-движков

## Новые backend — 26.10.2026

Интеграция Qwen3-ASR-1.7B + ForcedAligner и нативного long-form VibeVoice-ASR
описана в [ASRModels.md](ASRModels.md): точные SDK/веса, режимы, ресурсы,
ошибки выравнивания и результаты проверок. Новые задания используют
`1.0.0-audio2-asr9-live1-diarization4-summary16`. Whisper-политика прежняя;
фоновый режим новых профилей закрыт до отдельной live-приёмки.

`ASREngineFactory` выбирает `whisper`, `qwen3`, `vibevoice-asr` по закреплённому
профилю. Qwen хранит отдельные `alignerID`/`auxiliaryModelIDs`; четыре legacy
роли и их исторические profile fingerprints не менялись. Backend/политика и
полные SHA зависимостей участвуют в новом profile fingerprint. RunInfo старого
pipeline не продолжается автоматически; готовый результат читается прежним путём.

Worker загружает только локальные проверенные компоненты. SDK snapshots
не содержат Hub-download/HTTP/Python. Отмена проверяется на prefill/токенах,
между окнами, после SDK и перед публикацией. ASR/aligner освобождаются с
процессом этапа; затем запускается отдельный глобальный SpeakerKit.

Тесты без весов покрывают выбор фабрики, полный комплект, fingerprint,
установку/повреждение/удаление зависимости, окна/origin/хвост/принадлежность,
raw alignment, ошибку/отмену, UI и прежний live seal/SHA путь. Реальные проверки
включаются только переменными окружения из [ASRModels.md](ASRModels.md).

Итоговый release build прошёл; 474 XCTest (0 ошибок, 15 opt-in пропусков),
63 Python и 8/8 форматов. Отдельные реальные Whisper/SpeakerKit и live-probe
прошли с запретом сети. Qwen BF16/8-bit и VibeVoice реально распознают короткий
RU/EN пример; Qwen на прежней встрече отклоняет некорректный raw alignment.
Все новые профили остаются экспериментальными, приёмка качества не завершена.
Полные числовые результаты и ограничения — [ASRModels.md](ASRModels.md).

## Интерфейсы и ответственность

- `Sources/LocalScribeCore/ASR.swift`: `ASRRequest`, `ASRResult`,
  `ASRInputMode`, `ASRCapabilities`, `ASRCheckpointLayout`.
  Core по-прежнему не импортирует WhisperKit, MLX или GUI.
- `Sources/LocalScribeWorker/ASREngine.swift`: протокол `ASREngine` с
  `capabilities` и `recognize(_:) async throws -> ASRResult`; единая
  `ASREngineFactory.make`. Фабрика разрешает каталог через `pinned(to:)`,
  выбирает backend закреплённого профиля ASR и загружает реализацию.
  `loadWhisper` — подмена загрузки для тестов, не пользовательская настройка.
- `SpeechRecognizer` — общая оболочка: проверка поддерживаемого режима,
  отмена до/после вызова движка. Она не содержит параметров Whisper.
- `WhisperASREngine` — загрузка локальных Whisper/tokenizer, декодирование,
  mapper, prefix retry и выключенные production-эксперименты.
  `WhisperASRWindowing` содержит перенесённые из Core алгоритмы выбора паузы
  и поиска пропусков. `WhisperRecognitionPolicy` доступна только реализации
  и явным техническим probes.
- `WhisperASRMetrics` переводит SDK timings в прежние числовые поля
  `ASRMetrics`. Общий код записи диагностики больше не импортирует SDK.
  Эти исторические encoder/decoder/fallback-поля описывают Whisper;
  новые движки не должны заполнять их выдуманными эквивалентами.
- `Pipeline` и `LiveTranscriber` вызывают одну фабрику и получают один
  контракт результата. Они присваивают стабильные ID, сохраняют части,
  проверяют целостность и собирают итоговую расшифровку.

Движок и recorder принадлежат одному последовательному вызову worker.
Протокол намеренно не обещает параллельную безопасность экземпляра SDK:
экземпляр нельзя разделять между задачами или actors. Существующий actor
`Pipeline`, actor итогов и MainActor UI сохранены; новый MainActor-код,
`@unchecked Sendable` или ослабление режима Swift не добавлялись.

`ASRCapabilities` сообщает поддерживаемые batch-режимы и доступность word
timings. `available` не означает, что слова всегда есть или что они точны:
конкретный сегмент может содержать пустой `words`. Числовая уверенность
не входит в контракт. Существующий `Segment.uncertain` остаётся качественной
пометкой результата, с прежней Whisper-эвристикой только в его адаптере.

## Аудио, время и окна

`ASRRequest` содержит URL локального нормализованного mono/16 кГц файла,
`originMs`, `availableEndMs`, `coreRange` и `mode`.

- Ноль файла соответствует `originMs` исходной записи.
- Движок вправе читать только `[originMs, availableEndMs)`, даже если файл
  физически длиннее. `availableEndMs` — абсолютный конец доступного звука,
  а не длительность файла. Отрицательный seek недопустим.
- `coreRange` — принадлежащий запросу интервал. Контекст не становится
  новой речью: адаптер отвечает за принадлежность и отсутствие повторной
  публикации контекста между соседними запросами.
- Результат содержит обычные `Segment`/`Word` в исходных миллисекундах.
  Не обнулять время частей, не прижимать начало к нулю, не вырезать паузы.
  Пересекающее границу слово может иметь начало вне `coreRange`; для Whisper
  принадлежность по середине сохраняется, само слово не обрезается.
- Общий запрос не ограничен 30 секундами. Ограничение всей записи до трёх
  часов и нормализованный формат относятся к текущему приложению.
  Будущий движок сам выбирает внутренние окна и при необходимости
  ресэмплинг, сохраняя перевод в исходную шкалу.

| Правило | Владелец |
| --- | --- |
| Core ≤28 с, вход SDK ≤30 с, реальный контекст по 1 с | Whisper |
| Первая пауза ~600 мс после 2 с, prefix retry ≤30 с | Whisper |
| `windowClipTime=0`, transcribe, autodetect, fallback=2, concurrency=1 | Whisper |
| `noSpeechProb`, `avgLogprob`, compression, placeholder и uncertainty | Whisper mapper |
| Части offline 300 с, live1 30 с и контекст live1 по 1 с | Существующий формат checkpoints/конвейер |
| SHA/PCM, seal, проверка fingerprint, стабильные ID и mergeParts | Общий конвейер/Core |
| Один глобальный SpeakerKit после полного ASR | Pipeline |

`ASRCheckpointLayout` явно отделяет частоту сохранения от максимального
окна модели. В этой сессии геометрия старого `live1` сохранена, включая
проверки `LiveASRPart`. Движок может работать с запросом длиннее 30 с
(проверено fake engine на 300 с), но текущий live-оркестратор передаёт
30-секундные части с ограниченным доступным контекстом. Если следующему
движку нужен больший live-контекст или другое покрытие, потребуется отдельное
версионированное расширение планировщика и читателей checkpoints. Нельзя
просто поменять константы `live1` и считать старые части совместимыми.

## Закрытые фрагменты и настоящий streaming

`.closedFragments` — повторные конечные batch-запросы по закрытым CAF.
Это не потоковый decoder и не обещание работы в реальном времени.
Незакрытые `.partial.caf` не читаются. До seal требуется правый контекст;
после seal обрабатывается и короткий хвост. `originMs` соответствует началу
собранного набора CAF, которое может быть раньше нужного левого контекста.

Настоящему streaming-движку понадобится отдельный session-контракт:
подача PCM, состояние decoder, промежуточные/окончательные гипотезы,
flush/finalize и правила фиксации частей. Этот контракт пока не реализован;
нельзя выдавать поддержку `.closedFragments` за его наличие.

## Отмена, ошибки и checkpoints

Общая оболочка проверяет отмену до и после движка; Whisper дополнительно
проверяет её перед каждым SDK-вызовом, после нормального возврата SDK и между
окнами. Отмена не может вернуть успешную новую часть. Ошибка загрузки или
prefix retry выходит наружу: первичный частичный текст не публикуется как
готовый результат. Предупреждения передаются через существующий callback
в JSONL warning, с прежними текстом и исходными таймкодами.

JSONL v1, один последовательный worker, EOF/группа процессов и дренирование
pipe не менялись. SDK stderr не сохраняется приложением. Числовая диагностика
не содержит текстов, токенов, путей или ошибок SDK.

`ASRPart`/`LiveASRPart`, manifest, RunInfo и завершённые результаты не
мигрируются. При продолжении проверяются прежний fingerprint, диапазон,
ID части, исходник, закреплённые SHA; live дополнительно проверяет закрытые
фрагменты, seal, PCM и непрерывное покрытие. Существующие JSON не переписываются
ради нового интерфейса. `activeRunId`/`pendingRunId` и порядок очереди прежние.

## Профили и совместимость

В `ModelProfile` добавлено необязательное `asrBackend`. Отсутствие поля
означает `whisper`. Явное `"whisper"` эквивалентно отсутствующему значению;
существующий `models.lock.json` не изменён. Все текущие Whisper-профили,
`tokenizerID`, закреплённые `RunInfo.modelIDs` и legacy-папки работают прежним
путём. Новый backend выбирается только фабрикой; неизвестный ID отклоняется
до загрузки Whisper, без попытки угадать SDK по имени модели.

Fingerprint всех существующих комплектов сохранён точно, включая старый
revision-only алгоритм четырёх исходных ролей. Для backend, отличного от
Whisper, ID включается в идентичность профиля: смена движка при прежних файлах
не позволяет принять старый checkpoint. Новое поведение конкретного движка
также потребует ревизии pipeline/контрольных точек. Текущие `RunInfo` и
fingerprint SummaryEngine не менялись.

## Отдельный aligner

Подключать его как необязательную композицию в фабрике: базовый ASR возвращает
текст/сегменты, обёртка движка вызывает aligner для того же аудио и текста,
затем возвращает `ASRResult` с проверенными словами. Отдельный SDK/protocol
aligner следует вводить с реальной интеграцией, а не с фиктивной реализацией.

Aligner должен сохранять текст, язык, порядок, IDs и исходную шкалу времени;
локальные секунды результата переводятся через тот же `originMs`. Проверять
доступный диапазон и отмену до/после SDK. Не создавать word timings или
confidence искусственно; отсутствие выравнивания представляется пустыми
`words`, а политика ошибки/повтора должна быть явно согласована и проверена.
Глобальная диаризация по-прежнему выполняется после готовой расшифровки.

Не добавлять aligner в обязательные `ModelRole.allCases` старых заданий:
`pinned(to:)` сейчас проверяет точный комплект четырёх ролей. При добавлении
реального ForcedAligner нужны необязательная зависимость профиля, закрепление
её ID/revision/полных SHA и участие в fingerprint **только для использующих её
новых заданий**. Старые RunInfo без этой зависимости должны оставаться
совместимыми. Для моделей без внешнего токенизатора потребуется такое же
явное расширение resolver/library; текущие четыре роли пока сохранены.

## Ограничения и следующий этап

Качество распознавания не объявляется улучшенным. Известные пропуски,
перевод реплик и ошибки word timings сохраняют прежний статус из
[ASRExperimentStatus.md](ASRExperimentStatus.md). Новая WER/DER-приёмка,
физический микрофон/TCC, GUI, сон/нагрузка и реальные три часа не выполнялись.
Техническое RU/EN-аудио и fake transcribe не заменяют независимый эталон.

Следующий этап: **Qwen3-ASR + ForcedAligner**, затем **VibeVoice-ASR**.
Для каждого: проверить реальный локальный runtime на Apple Silicon, лицензии
и формат весов, добавить закреплённые профили/необязательные зависимости,
реализовать ASREngine и фабрику, определить внутренние окна/доступный контекст,
проверить offline и закрытые CAF, отмену/ошибки/возобновление и таймкоды.
Streaming заявлять только после отдельной реализации session-контракта.
Изменения политики, геометрии live и aligner должны получить собственную
версию/идентичность; затем нужен новый независимый набор для сравнения качества.
