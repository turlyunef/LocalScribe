# Новые микрофонные записи: PCM16 / 16 кГц

Изменение от 19.10.2026. Новые CAF-фрагменты и `source/original.caf` содержат
моно signed PCM16 / 16 кГц: 32 000 байт/с, 115,2 МБ/час или 345,6 МБ за три
часа, без небольших заголовков CAF. Это в шесть раз меньше прежнего
моно Float32 / 48 кГц. Импорт сохраняет исходный файл без перекодирования;
готовые записи, их SHA и контрольные точки не мигрируют.

## Тракт записи

Tap по-прежнему принимает частоту устройства, сводит каналы в моно Float32
и копирует звук в ограниченный пул из 32 буферов. На последовательной
writerQueue `MicrophoneCaptureWriter` использует один `AVAudioConverter`
на всю сессию с максимальным качеством ресэмплинга и normal priming.
Конвертер не сбрасывается ни между callback, ни на границах CAF.
[Apple TN3136](https://developer.apple.com/documentation/technotes/tn3136-avaudioconverter-performing-sample-rate-conversions)
описывает используемый потоковый API преобразования частоты.

Вход передаётся конвертеру один раз, затем `.noDataNow` дренирует доступный
выход до возврата буфера в пул. При остановке `.endOfStream` выгружает хвост
фильтра. Normal priming компенсирует задержку фильтра; в начале записи не
добавляется искусственный сдвиг шкалы времени. Длина округляется конвертером
до сэмпла выходной частоты; очень короткий вход менее половины сэмпла может
не дать выходного звука.

Конвертер выдаёт Int16 в постоянный выходной буфер; ещё два постоянных
буфера нужны для разрезания выхода на CAF и обрезания последнего входа по
лимиту. Приложение не создаёт новый AVAudioPCMBuffer на каждую порцию.
Каждый полный CAF содержит 160 000 сэмплов. После закрытия, fsync и
переименования он доступен фоновому ASR. Пустые фрагменты не создаются.
Ошибка преобразования/записи сохраняется: дальнейшие вызовы не публикуют
незавершённый фрагмент как успешный.

Лимит трёх часов отсчитывается по принятым входным кадрам, чтобы задержка
конвертера не разрешала принять лишний звук. Итоговое число кадров,
индикатор времени и пороги meter используют 16 кГц. Начальная проверка
места требует 1,2 ГБ: три копии трёхчасового PCM16 (фрагменты, оригинал,
рабочий WAV) занимают около 1,04 ГБ. После каждого полного CAF остаётся
проверка места на сборку оригинала и резерв 500 МБ.

## Оригинал, совместимость и восстановление

`Media.assembleCaptureParts` использует `fileFormat.settings` первого CAF,
а не его Float32 processing format. Все части должны иметь одинаковые
файловый и рабочий форматы. Поэтому новые оригиналы остаются PCM16,
а старые Float32-фрагменты восстанавливаются в Float32 на прежней частоте.

Проверки SHA, seal и точного PCM в `CaptureIntegrity` сохранены. Int16
точно представим в Float32, который используется для сравнения; тест
проверяет побитовое совпадение декодированного PCM частей и оригинала.
Незавершённые `.partial.caf` по-прежнему исключаются из восстановления.
Фрагменты live ASR удаляются только после проверенного присоединения
контрольных точек и выхода worker.

Схема manifest/run, анализ и prompt не меняются. Новая запись получает
собственную сессию и SHA, поэтому изменение хранения не требует
инвалидации заданий или контрольных точек уже сохранённых записей.

## Автоматические и ручные проверки

`MicrophoneCaptureWriterTests` проверяет частоты 8/16/44,1/48/96 кГц,
равенство PCM при входных порциях 1024 и 8192 кадра, повторное использование
пула, два стыка CAF и хвост 125 мс, сохранение PCM16 при сборке и проверку seal.
Отдельные тесты проверяют тихий тон 0,0005 (около −66 dBFS) без сдвига/провалов
на стыках, квантование и насыщение PCM16, короткие и пустые записи, повторное
закрытие, обрезание по лимиту и выгрузку хвоста. Для проверки предела
используется тот же алгоритм с длительностью 20 секунд вместо трёх часов.
Также проверяется восстановление только закрытых частей и побитовое
сохранение старого Float32 вместе с неизменностью SHA его фрагментов.
`LiveCaptureTests` проверяет присоединение нового PCM16 и повторную
публикацию без изменения контрольной точки.

```sh
swift test -c release -j 4 --force-resolved-versions --filter 'MicrophoneCaptureWriterTests|LiveCaptureTests'
swift test -c release -j 4 --force-resolved-versions
```

Проверено 19.10.2026: 15 целевых тестов прошли без ошибок; полный release-прогон —
245 XCTest (124 Core, 83 UI/service, 38 диаризации), 0 ошибок, 2 ожидаемых
модельных пропуска. Логи сохранены в исключённой из Git папке
`TestResults/capture-pcm16/`. Использованы имеющиеся Metal-артефакты; чистая
сборка Metal не проверялась. Установленная `.app` не обновлялась.

Синтетический тихий тон проверяет тракт, но не качество распознавания тихой
речи. Ресэмплер AVAudioConverter отличается от прежнего FFmpeg, поэтому
побитовое равенство прежнему входу моделей не обещается. По
[MacAcceptance](MacAcceptance.md) остаются настоящая запись с микрофона,
стресс под нагрузкой, принудительное завершение и трёхчасовая встреча;
нужно сравнить тихую речь, слова на стыках и WER/DER на одном реальном
контрольном наборе. Профиль аллокаций из [прежнего отчёта](CaptureWriterAllocations.md)
после добавления конвертера требует нового замера.
