# Запись звука: PCM16 / 16 кГц

Изменение от 19.10.2026. Новые CAF-фрагменты и `source/original.caf` содержат
моно signed PCM16 / 16 кГц: 32 000 байт/с, 115,2 МБ/час или 345,6 МБ за три
часа, без небольших заголовков CAF. Это в шесть раз меньше прежнего
моно Float32 / 48 кГц. Импорт сохраняет исходный файл без перекодирования;
готовые записи, их SHA и контрольные точки не мигрируют.

## Тракт записи

Микрофон закрепляется через AVAudioEngine. У входов Bluetooth, которые HAL
показывает отдельным устройством без выхода, приложение читает входной поток
напрямую. При включении микрофона AirPods HAL может перейти с 48 на 24 кГц,
пока AVAudioEngine ещё сообщает прежний формат. Перед началом записи
проверяется получение первого пакета микрофона. Если Core Audio остановил
движок во время запуска, LocalScribe проверяет закреплённый вход, даёт HAL
завершить смену конфигурации и перезапускает движок в пределах исходного
таймаута. Для допуска нужен новый пакет после перезапуска. Системный звук
поступает из приватного глобального Core Audio process tap через приватное агрегатное
устройство. Tap исключает процесс LocalScribe и сохраняет обычное
воспроизведение. HAL сообщает ошибки захвата отдельно от уровня. Поток
с валидными временными метками и нулевым PCM показывает «Системный звук
пока не поступает».

Callbacks копируют моно Float32 в общий пул из 48 буферов. Приём буфера и
его постановка на writerQueue защищены одной блокировкой, поэтому
закрытие писателя ждёт уже принятый звук. `TimedCaptureWriter` сопоставляет
временные метки начала пакетов с общей монотонной шкалой 16 кГц,
компенсирует дрейф частоты и фильтрует сигнал перед понижением частоты.
В смешанном режиме первый принятый пакет задаёт начало шкалы. Системный звук
сохраняется во время проверки микрофона. Ожидание разрешения Core Audio
не добавляет тишину перед первым пакетом. Пропуски заполняются тишиной на
шкале соответствующего источника. Пакеты с меткой более чем на две секунды
впереди хост-часов отбрасываются.
Микшер суммирует сигналы с исходным усилением. Если сумма приближается к
пределу PCM16, мягкий ограничитель сжимает только пики. Тишина второго
источника сама по себе не уменьшает уровень первого.
Если источник потерян, оставшийся продолжает запись на прежней шкале.
Индикатор громкости показывает уровень входных пакетов, даже когда микшер
ещё ждёт данные второго источника. Если HAL сообщает, что выбранный
микрофон выключен, приложение показывает отдельное сообщение о микрофоне.

Если в настройках выбран конкретный вход, его UID остаётся предпочтительным.
При запуске и во время записи доступные физические внешние входы служат
резервом, за ними следует встроенный микрофон. При возвращении
предпочтительного устройства приложение проверяет его параллельно с рабочим
входом. После первого валидного пакета и проверки формата оно переключает
допуск и закрывает прежний вход. При неудачной проверке прежний микрофон
продолжает передавать PCM. Принятые пакеты старого входа сохраняются, а
поздние callbacks от предыдущего подключения или аудиотапа отбрасываются.

При потере микрофона с подтверждённым Mute захват голоса ждёт кнопки
«Включить запасной микрофон». Если микрофон не запустился, в смешанном режиме
запись начинается с системного звука, показывает предупреждение и повторяет
попытку подключения микрофона. При потере микрофона после запуска системный
звук продолжает записываться. Если запись только с микрофона и
попытка восстановления истекла, приложение сохраняет уже записанное.

Каждый полный CAF содержит 160 000 сэмплов. После закрытия, fsync и
переименования он доступен фоновому ASR. Пустые фрагменты не создаются.
Лимит трёх часов применяется к общей шкале и итоговому числу кадров.
Начальная проверка места требует 1,2 ГБ. Три копии трёхчасового PCM16
(фрагменты, оригинал, рабочий WAV) занимают около 1,04 ГБ. После каждого
полного CAF остаётся проверка места на сборку оригинала и резерв 500 МБ.

## Оригинал, совместимость и восстановление

`Media.assembleCaptureParts` использует `fileFormat.settings` первого CAF,
а не его Float32 processing format. Все части должны иметь одинаковые
файловый и рабочий форматы. Поэтому новые оригиналы остаются PCM16,
а старые Float32-фрагменты восстанавливаются в Float32 на прежней частоте.

Проверки SHA, seal и точного PCM в `CaptureIntegrity` сохранены. Int16
точно представим в Float32, который используется для сравнения; тест
проверяет побитовое совпадение декодированного PCM частей и оригинала.
Незавершённые `.partial.caf` по-прежнему исключаются из восстановления.
Фрагменты live ASR удаляются только после проверенного присоединения
контрольных точек и выхода worker.

Схема manifest/run, анализ и prompt не меняются. Новая запись получает
собственную сессию и SHA, поэтому изменение хранения не требует
инвалидации заданий или контрольных точек уже сохранённых записей.

## Автоматические и ручные проверки

`MicrophoneCaptureWriterTests` проверяет частоты 8/16/44,1/48/96 кГц,
равенство PCM при входных порциях 1024 и 8192 кадра, повторное использование
пула, два стыка CAF и хвост 125 мс, сохранение PCM16 при сборке и проверку seal.
Отдельные тесты проверяют тихий тон 0,0005 (около −66 dBFS) без сдвига/провалов
на стыках, квантование и насыщение PCM16, короткие и пустые записи, повторное
закрытие, обрезание по лимиту и выгрузку хвоста. Для проверки предела
используется тот же алгоритм с длительностью 20 секунд вместо трёх часов.
Также проверяется восстановление только закрытых частей и побитовое
сохранение старого Float32 вместе с неизменностью SHA его фрагментов.
`LiveCaptureTests` проверяет присоединение нового PCM16 и повторную
публикацию без изменения контрольной точки.

```sh
swift test -c release -j 4 --force-resolved-versions --filter 'MicrophoneCaptureWriterTests|LiveCaptureTests'
swift test -c release -j 4 --force-resolved-versions
```

Проверено 19.10.2026: 15 целевых тестов прошли без ошибок; полный release-прогон —
245 XCTest (124 Core, 83 UI/service, 38 диаризации), 0 ошибок, 2 ожидаемых
модельных пропуска. Логи сохранены в исключённой из Git папке
`TestResults/capture-pcm16/`. Использованы имеющиеся Metal-артефакты; чистая
сборка Metal не проверялась. Установленная `.app` не обновлялась.

Синтетический тихий тон проверяет тракт, но не качество распознавания тихой
речи. Ресэмплер AVAudioConverter отличается от прежнего FFmpeg, поэтому
побитовое равенство прежнему входу моделей не обещается. По
[MacAcceptance](MacAcceptance.md) остаются настоящая запись с микрофона,
стресс под нагрузкой, принудительное завершение и трёхчасовая встреча;
нужно сравнить тихую речь, слова на стыках и WER/DER на одном реальном
контрольном наборе. Профиль аллокаций из [прежнего отчёта](CaptureWriterAllocations.md)
после добавления конвертера требует нового замера.
