# Время подготовки итогов

`SummaryEngine` сохраняет `metrics-summary.json` в каталоге run. Это диагностика
одного вызова summary: при продолжении начинается новый замер. Файл атомарно
обновляется перед запросом, после его завершения и проверки ответа, а также
при возврате или ошибке этапа. Он содержит только счётчики, длительности и
фиксированные названия этапов. Текст, цитаты, ID реплик, пути моделей и сообщения
ошибок SDK в него не попадают. Число групп статистики ограничено независимо
от длительности встречи; история запросов в памяти не накапливается.

## Что измеряется

- `modelLoadSeconds` — время `LLMModelFactory.loadContainer`. Подготовка первого
  inference, которую SDK выполняет после возврата загрузчика, относится к запросу.
- `sourcePreparationSeconds` — подготовка строк, индекса и токеновых границ частей.
- `planningTokenizations` / `planningSeconds` — число и время токенизаций полных
  chat prompts при планировании проверок, включая бюджет второй попытки.
- `phases` — отдельные счётчики для четырёх разделов extraction, сведения обзора,
  проверки решений/задач, поздних уточнений, применения уточнения и закрытия вопросов.
- `requests` / `completedRequests` — начатые и вернувшиеся обращения к генератору.
  `retries` считает реально выполненные вторые попытки, включая неудачные.
  `checkpointHits` и `groupCheckpointHits` показывают повторное использование
  проверенных результатов, а не обращения к модели.
- `inputTokens` — сумма размеров фактически подготовленных chat inputs;
  `reservedOutputTokens` — сумма лимитов ответа; `outputTokens` — фактические
  токены из `GenerateCompletionInfo`, включая отвергнутые и усечённые ответы.
  Резерв не подставляется вместо фактического выхода. При отсутствии SDK info
  растёт `missingCompletionInfo`; незавершённый запрос виден по разнице счётчиков.
- `preparationSeconds` — подготовка реальных inputs и проверка thinking;
  `wallSeconds` — полное время обращений к генератору;
  `promptSeconds` / `generationSeconds` — времена prefill и decode из SDK;
  `maximumRequestSeconds` — самый медленный запрос категории.
- `validationFailures` — ответы с EOS, не прошедшие JSON/смысловую проверку
  или проверку цитаты. `stoppedAtEOS`, `stoppedAtLimit`, `cancelled`, `errors`
  отдельно описывают завершение генератора. Отрицательный, но корректный вердикт
  проверки факта не считается ошибкой валидации.

Длительности верхнего уровня и обращений измеряются монотонными часами;
`startedAt` сохраняется в ISO 8601. При принудительном завершении через `_exit`
последний снимок остаётся со статусом `running`: это не завершённый замер.
Ошибка записи диагностики не отменяет проверенный результат. Старый
`llm-audit.json` сохраняет прежний смысл: реальная пара вход/резерв самого
большого контекста с пределом 8192 и флагами thinking/EOS.

## Повторение технического замера

Сначала получить release worker:

```sh
swift build -c release -j 4 --force-resolved-versions
swift build -c release --show-bin-path
```

Затем указать реальный путь worker и каталог run синтетического technical-probe:

```sh
python3 scripts/probe_summary_speed.py \
  --reference-run TestResults/<technical-recording>/runs/<run-id> \
  --worker <release-bin-path>/LocalScribeWorker \
  --output TestResults/summary-speed-new \
  --count 3 --check-resume
```

Скрипт не меняет исходный run. Он проверяет SHA аудио, fingerprint расшифровки,
размеры и SHA всех файлов выбранной summary-модели, создаёт новые UUID-каталоги
и закрепляет четыре выбранных профиля и текущую версию pipeline в новом задании.
SHA исходной расшифровки и версия исходного pipeline остаются в `environment.json`. Старые smoke-пробы
могли хэшировать весь каталог альтернатив; это значение не переносится в
новый `profileHash`. Worker и существующий metallib копируются в отдельную
папку внутри результата. Приложение не упаковывается и не переподписывается;
сетевая изоляция и EOF-протокол worker сохраняются. SDK stderr отбрасывается.

Каждый `fresh-*` выполняет все запросы без summary checkpoints и загружает модель
в новом процессе; файловый кэш macOS при этом может быть прогрет. `resume-*`
повторяет тот же run, сохраняет отдельный снимок метрик и проверяет неизменность
checkpoint-файлов и конечного `summary.json`. Скрипт не запускает ASR/диаризацию. `environment.json`
закрепляет SHA worker, metallib, каталога, исходника и расшифровки, профиль
модели и версию pipeline. `fresh-*.json`, `resume-*.json` и `results.json`
содержат время процесса и снимки метрик. Все артефакты остаются в `TestResults`.

Синтетический короткий пример служит для анализа затрат, а не для оценки
качества итогов или производительности многочасовой встречи. Удаление проходов,
объединение языков и изменение prompt требуют отдельного сравнения полноты
фактов, цитат, поздних отмен и ответов на вопросы.

## Контроль 19.10.2026

Использована неизменённая расшифровка `mixed.wav` из полного контрольного
анализа аудита памяти: 22,2435625 секунды, четыре реплики на русском/английском.
В новом задании пересчитываются только итоги. SHA аудио:
`bfade6873f6b0c97df5f86925a3715fbcd4a55c2d49c7ff456a15e67af069d6b`.
Профиль `summary`, ревизия `8b2b98c00a6b4d291155e4890773ca8f769aee53`;
совпали размеры и SHA всех 12 файлов модели. macOS 27.0.1, arm64,
MLX Swift LM 2.31.3, release worker с имеющимся metallib. Чистая сборка
Metal и упаковка `.app` для этого замера не выполнялись.

Время процесса — **352,938 s** против **345,620 s** из исходного аудита.
Это два отдельных запуска, а не доказательство изменения скорости на 2%.
Загрузчик модели занял **1,884 s**, подготовка исходника — **0,007 s**,
планирование токеновых бюджетов — **1,724 s**, подготовка реальных inputs —
**0,798 s**. SDK сообщил **192,084 s prefill** и **154,751 s decode**.
Все 18 ответов завершились с EOS; повторных попыток, усечений и ошибок
валидации не было. Таким образом, задержку этого примера объясняют
восемь отдельных extraction-запросов и десять проверок, прежде всего
повторная обработка полного chat input моделью. CPU-токенизация и
загрузка модели дают малую часть общего времени.

Обнаружена отдельная ошибка продолжения: второй запуск того же run занял
**130,312 s** и повторил **9 запросов** (7171 входной / 324 выходных токена).
Extraction-группа и проверка вопроса были взяты из checkpoints; проверки
оснований и позднего уточнения пересчитались. Скрипт зафиксировал изменение
уже существовавших checkpoint-файлов. Причина — `JSONEncoder()` без
`.sortedKeys` в `SummaryEngine.verify`: порядок ключей JSON кандидата менял
fingerprint без изменения фактов, а также текст кандидата для поздней проверки.

Артефакты исходного измерения:
`TestResults/summary-speed-2026-10-19-runtime/{environment,fresh-0,resume-0}.json`.
Завершение скрипта с ошибкой в этом каталоге ожидаемо: проверка неизменности
checkpoints обнаружила дефект. Неудачные старты в ограниченной среде
`summary-speed-2026-10-19-baseline` и `summary-speed-2026-10-19-measured`
не использованы как измерения производительности.

## Исправление продолжения

`verify` теперь всегда использует `.sortedKeys`, включая вызов из продукта.
Тесты больше не подменяют encoder своим стабильным экземпляром. Отдельная
регрессия проверяет канонические fingerprints обоих видов checkpoint и
неизменность их байтов при повторных вызовах; до исправления она воспроизвела
несовпадения обоих fingerprints и лишнее обращение к fake model.
Метаданные попытки/назначения и callback валидации в `SummaryReviewModel`
служат только диагностике и не входят в chat input.

Из-за изменения сериализации кандидата позднего уточнения и fingerprints
версия повышена до `summary14` / `prompt-v14`. Схема конечных `Summary` и
`Transcript` сохраняется. Старые результаты читаются; существующие задания
`summary13` остаются на диске, но требуют «Обработать заново» вместо продолжения
в другой версии pipeline. Никакие старые checkpoints не переписываются при
проверке совместимости в GUI. Подсчёт контекста, EOS, валидация JSON,
основания, точные цитаты, все поздние реплики и разделение extraction по
разделам/языкам сохраняются. MLX cache limit, очистка кэша и диаризация не менялись.

Для первого расчёта основной объект дальнейшего эксперимента — повторный prefill
общих частей chat input. Измерение не даёт основания удалять проверки или
объединять независимые разделы. Также оно не показывает необходимости
принудительно очищать MLX-кэш после запросов.

Проверка кода: `swift test -c release -j 4 --force-resolved-versions` —
**228 XCTest, 0 ошибок, 2 ожидаемых модельных пропуска** (123 Core,
67 UI/service, 38 worker/диаризация). Включены проверки повторных попыток
после неверной цитаты, метаданных типа/номера запроса, сохранения безопасной
диагностики при ошибке загрузки и сброса её счётчиков на новый вызов.
Новый файл метрик учитывается при определении происхождения legacy-итогов:
он не позволяет принять автоматически созданный run за ручную редакцию
без обязательных оснований. Лог — `TestResults/summary-speed-tests.log`;
воспроизведение дефекта до исправления — `summary-speed-regression-before.log`.

## Контроль после исправления

Новый run с `summary14`, та же исходная расшифровка и те же закреплённые веса:

| Запуск standalone worker | До исправления | После исправления |
| --- | ---: | ---: |
| Полный первичный расчёт | 352,938 s / 18 запросов | 490,792 s / 18 запросов |
| Повторный запуск с checkpoints | 130,312 s / 9 запросов | **1,841 s / 0 запросов** |

Повторный запуск использовал одну extraction-группу и десять checkpoints
проверок. SHA всех checkpoint-файлов и конечного `summary.json` после него
побайтово совпали с сохранёнными после первичного расчёта. Оба процесса
завершились кодом 0. Таким образом, устранена повторная работа при продолжении
с совместимыми checkpoints, без пропуска незавершённых проверок.

Первичный контроль после исправления: **14259 входных / 1900 выходных токенов**,
**0 повторных попыток**, усечений или ошибок валидации. Загрузка — **2,959 s**,
prefill — **275,807 s**, decode — **204,286 s**. Первые восемь extraction-запросов
в обоих запусках имеют одинаковые входные и выходные счётчики, но разные
длительности. Эти два запуска не позволяют приписать разброс времени исправлению
fingerprints или заявить ускорение первичного расчёта. Отдельная серия с
контролем системной нагрузки потребуется для настройки prefill; удаление
проверок фактов по этим данным не обосновано.

Артефакты после исправления:
`TestResults/summary-speed-2026-10-19-fixed/{environment,fresh-0,resume-0,results}.json`.
Контрольный скрипт завершился успешно; лог — `TestResults/summary-speed-fixed-probe.log`.
