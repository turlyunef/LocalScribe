# R12: сохранение и восстановление архива — 18.10.2026

`RecordingRepository.save` атомарно записывает только `manifest.json` через `Disk.write`, без перечисления архива и записи `index.json`. Низкоуровневое удаление также не сканирует оставшиеся записи. Формат файлов не изменён.

`RecordingCoordinator` — единственный владелец архивных транзакций GUI. Его actor последовательно выполняет чтение, изменение и сохранение manifest вне MainActor. `update` применяет изменение к актуальной записи без suspension между чтением и записью: переименование, предупреждения и смена этапа не перезаписывают поля друг друга. Проверки результатов, сборка CAF, SHA и очистка используют тот же исполнитель. UI и очередь worker остаются на MainActor.

Coordinator хранит снимок списка и позиции записей по ID. После успешной записи меняется только соответствующий элемент; ошибка записи не публикует новый снимок. `AppModel.reload` получает снимок без файловых чтений и публикует его только при новой ревизии. Ответ со старой ревизией не заменяет новый список. Добавление и удаление обновляют порядок/позиции в памяти. `refresh(id)` явно подхватывает известное внешнее изменение; полный обход при обычном reload не выполняется.

Индекс строится из снимка с объединением изменений за 250 мс. Перед выходом выполняется `flushIndex`; после удаления индекс обновляется сразу. Ошибка индекса не отменяет уже сохранённый manifest. Запуск всегда читает manifests, поэтому отсутствующий, повреждённый или устаревший индекс не скрывает записи. Сбой между публикацией manifest и индекса оставляет восстановимую запись.

`recover` один раз перечисляет архив и читает каждый допустимый manifest. Оба состояния обработки и предупреждение о прерванном микрофоне сохраняются одной записью на элемент. Очистка использует уже прочитанный manifest; в конце один раз записывается индекс из полученного массива, который также возвращается coordinator. Повторное восстановление не переписывает неизменённые manifests и не добавляет повторное предупреждение. Проверки SHA, сохранение active/pending run, повреждённых элементов и исходников остаются в силе.

`WorkerSupervisor` ожидает асинхронный обработчик события: предупреждение успевает сохраниться до публикации финального состояния. Ожидающее чтение при enqueue проверяет актуальность запроса после suspension; отмена/пауза не запускает старый запрос. FIFO резервируется до сохранения, worker ждёт завершения этой записи.

## Проверки и замеры

Команда: `swift test -c release -j 4 --force-resolved-versions`.

Финальный прогон: **196 XCTest — 112 Core, 57 UI/service, 27 диаризации; 0 ошибок, 2 модельных пропуска**.

Фикстуры создаются в случайных временных каталогах и удаляются; пользовательский архив и модели не используются. Счётчик I/O отмечает реальные обращения repository к manifest, обходам и записи индекса, без содержимого записей.

- `RepositoryPerformanceTests`: 250/1000 записей, одна финальная запись индекса, идемпотентность, повреждённый/недоступный индекс, имитация сбоя между manifest и индексом через повторное открытие, неудачная запись manifest, объединение записей индекса и конкурентные изменения одного элемента.
- `ArchiveResponsivenessTests`: запуск GUI на 1000 записях, 100 reload, 100 изменений с reload, отсутствие архивного I/O на главном потоке и интервалы MainActor с периодом проверки 1 мс.
- `ProcessingQueueTests`: предупреждения вместе с переименованием, отмена/пауза при заблокированном чтении, прежние сценарии FIFO, live capture, ошибок и продолжения.

Измерения выполнены release-сборкой на текущем Apple Silicon Mac со Swift 6.4; время подготовки/удаления фикстур исключено. Это локальные наблюдения, а не гарантия задержки на любом диске. Таймер включает планирование ОС и фоновые задачи приложения. Во время раннего прогона с компиляционной нагрузкой его максимальный интервал достигал 27,8 мс.

Исходный квадратичный вариант по времени не замерялся; тесты фиксируют линейное число чтений исправления. Полный лог прогона хранится локально в `TestResults/r12-tests.log` и не коммитится.

Сборка использует имеющиеся Metal-артефакты; чистая сборка Metal и подписанная `.app` этим прогоном не проверяются.
