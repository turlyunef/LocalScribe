# Освобождение ресурсов при штатном завершении worker

Проверено 19.10.2026: Apple M1 / 16 GiB, macOS 27.0.1 (26A434),
Swift 6.4, release-сборка. Разобраны три небольших блока из отчёта памяти,
найденные Leaks при завершении полноценного ASR через обычный JSONL.

## Находка и исправление

Свежий контрольный прогон текущего worker до правки повторил **3 блока /
688 байт**: `__DataStorage` 80 байт, буфер команды 448 байт и watchdog
`dispatch_source_t` 160 байт. Анализ ASR завершился кодом 0, офлайн-анализ
memory graph — кодом 1, означающим найденные блоки.

`exit` вызывался внутри `async main`, пока его локальные переменные ещё
существовали. Такой вызов не выполняет обычный выход из Swift-области
видимости. Кроме того, блокирующее ожидание EOF продолжало удерживать
команду и emitter до завершения процесса. Эти стартовые объекты не являются
доказательством накопления памяти на каждом ASR-окне.

Теперь путь завершения устроен так:

1. `readCommand` синхронно читает и декодирует одну строку внутри локального
   autorelease pool. Временные строка и `Data` не переходят в обработку этапа.
2. `runCommand` выполняет этап и сохраняет метрики, затем возвращает только
   код и финальное событие. Контекст pipeline выходит из своей области жизни.
3. Actor `WorkerControl` отменяет timer watchdog и `DispatchSourceRead`,
   наблюдающий EOF. Он ожидает оба cancellation handler на последовательной
   очереди; callbacks и захваченный ими emitter освобождаются до продолжения.
4. Worker публикует `completed` или `failed`, закрывает выделенный протокольный
   дескриптор и возвращает код. Только после этого `main` вызывает `exit`.

В отличие от блокирующего `readDataToEndOfFile`, источник чтения можно
отменить, когда stdin всё ещё открыт у GUI. Дескриптор stdin заимствован;
наблюдатель не закрывает его. Отмену источника нужно дождаться до закрытия
его дескриптора: это требование [Dispatch](https://developer.apple.com/documentation/dispatch/dispatch_source_set_cancel_handler_f).

EOF по-прежнему отправляет `cancelled` и принудительно завершает группу
с кодом 72; потеря родителя — с кодом 71. Оба пути сохраняют `_exit`, чтобы
не запускать деструкторы MLX одновременно с inference. Штатный путь продолжает
использовать `exit`, поэтому Leaks `--atExit` действительно выполняется.
JSONL v1, схема хранения, fingerprint, sandbox и сетевой запрет не изменены.
Диагностическая диаризация тоже возвращает код через штатную очистку.

## Повтор Leaks

| Worker | Полных ASR-процессов | Блоки / байты Leaks | Коды ASR / анализа graph |
| --- | ---: | --- | --- |
| Контроль до правки | 1 | 3 / 688 | 0 / 1 |
| Исправленный | 3 | 0 / 0 в каждом | 0 / 0 в каждом |

Каждый процесс использовал исходную синтетическую фикстуру 22,24 s и реальные
веса Whisper. В копии записи удалялись ASR checkpoints, чтобы модель реально
выполнила распознавание. Вход оставался обычным JSONL через stdin, открытым
до завершения worker. `MallocStackLogging=1`, `leaks --atExit`, графы
сохранялись с `--noContent`, затем независимо перечитывались `leaks`.
SDK stderr отбрасывался. Пользовательский архив и подпись `.app` не менялись.
Сборки и другие модельные прогоны одновременно с Leaks не выполнялись.

Три нулевых результата подтверждают устранение исходной находки в этом
сценарии. Они не доказывают отсутствие всех возможных утечек в GUI или ML SDK.

Локальные артефакты исключены из Git:
`TestResults/worker-lifetime-fix-2026-10-19/`: контрольный и исправленный
бинарники/исходники, `baseline`, `fixed-first`, `fixed-repeats`,
memory graph, полные стеки, результаты и журнал XCTest.

## Регрессии

`WorkerLifecycleTests` проверяет одну строку команды, Unicode, EOF,
невалидный JSON и версию; освобождение обоих callbacks, сохранение
заимствованного дескриптора, повторный `stop`, дренирование дополнительных
байтов и ожидание уже выполняющегося callback перед завершением `stop`.

Интеграционные проверки собранного worker после правки:

- 10/10 отмен загруженной Qwen: код 72, без SIGSEGV; исходник и checkpoints
  не изменились, группы процессов исчезли, FD родителя — 3 до / 3 после.
- Потеря тестового родителя с закрытием stdin: worker и контролируемый
  дочерний процесс завершились.
- Отдельная потеря родителя с оставшимся открытым stdin: сработал watchdog,
  worker и дочерний процесс завершились, события `cancelled` не было.
- Пустой stdin, невалидный JSON и неподдерживаемая версия: код 64; ошибка
  pipeline при открытом stdin: код 1 и события `started`, `failed`.

Команды сборки и тестов:

```sh
swift build -c release -j 4 --force-resolved-versions
swift test -c release -j 4 --force-resolved-versions
```

Полный release-прогон: **225 XCTest** (122 Core, 67 UI/service,
36 диаризации/worker), **0 ошибок**, 2 ожидаемых модельных пропуска.

В текущей локальной среде повторить Leaks на сохранённой технической фикстуре
можно после сборки без изменения источников/моделей:

```sh
python3 TestResults/worker-lifetime-fix-2026-10-19/leaks_jsonl.py --label new-repeat --count 3
```

Harness и фикстуры находятся только в локальном `TestResults`; это не команда
для чистого checkout. Новый label должен отсутствовать: прошлые graphs и
результаты не перезаписываются. Сам harness использует только синтетический
reference из исходной проверки, создаёт отдельные копии и удаляет их после
успешного сохранения графа. Анализировать пользовательские записи для повтора
не требуется. Использованы имеющиеся Metal-артефакты; чистая сборка Metal
и упаковка `.app` не проверялись.
