# Поиск по названиям записей

Реализация по [RecordingTitleSearchSpec.md](RecordingTitleSearchSpec.md), 24.10.2026.

Под «Записи» находится постоянное поле с правой декоративной лупой. Любой исходный символ заменяет лупу кнопкой очистки. Поиск применяется при вводе, без Enter и debounce; Command+F переводит фокус в поле и выделяет запрос, сохраняя собственный поиск других текстовых редакторов. Первый Escape очищает текст, следующий снимает фокус. Нормализация не записывается обратно в поле и не меняет композицию IME.

`RecordingTitleSearch` в Core нормализует NFKC, case folding en_US_POSIX и ё/е, сохраняя остальные диакритические знаки. Сопоставление: AND по уникальным токенам, точный внутренний фрагмент либо полосатое OSA относительно допустимых префиксов слова. Бюджеты 0/1/2 зависят от длины 1–3/4–7/8+ графем; запрос с цифрами допускает только точное вхождение. Буферы трёх строк DP переиспользуются. Индекс интернирует слова и пути префиксов; в пределах запроса одинаковые слова и ограниченные префиксы используют общий результат. Это точная мемоизация, без отсечения кандидатов.

`AppModel` владеет `RecordingSearch`; sidebar и заголовки групп непосредственно наблюдают поиск. Любая замена `recordings` актуализирует проекцию ID/названий и расположения. Статус не увеличивает ревизию корпуса и не перестраивает индекс. Группировка и сортировка выполняются в фоне; строки берут актуальные manifests из AppModel. Метод `recordings(in:)` сохраняет полный состав группы для операций.

Исполнитель содержит один detached handle и один заменяемый pending-запрос. Новый ввод отменяет handle; следующая CPU-задача начинается после завершения прежней. Публикация проверяет поколения запроса, корпуса и расположения. Удалённые ID исчезают из текущих данных сразу. Очистка использует готовое обычное представление; shutdown запрещает дальнейшие публикации. Обновление только статуса не ждёт выполняющегося поиска.

В поиске раскрытие групп временное. Новый нормализованный запрос снова раскрывает группы; очистка возвращает сохранённое состояние. Счётчики показывают совпадения/полный состав. Пустые группы скрываются, активный редактор имени остаётся доступен. Перестановка групп отключена; перенос записей и меню назначений используют реальный каталог всех групп. Скрытое фильтром множественное выделение и опора диапазона исключаются из действий, primary selection и открытый результат сохраняются. Запросы и индекс существуют только в памяти; поиск не вызывает архивного I/O.

## Проверки

Core-тесты проверяют все примеры спецификации, Unicode и числовые токены, бюджеты, четыре операции, независимый полный OSA-oracle, 15 000 сравнений полосатого префиксного matcher и 37 500 сравнений подготовленного индекса с oracle. Проверены повторное использование индекса и одинаковые названия с разными ID.

Интеграционные тесты используют управляемый executor с continuation-барьерами: последняя pending-работа, единственный исполнитель, A→B→A, поздние ответы, смена корпуса/членства, очистка и shutdown. Временные архивы проверяют сохранность каталога, индекс при смене статуса, отсутствие manifest/index/scan I/O при вводе, выбор и перенос. Нативные mouse-down/Shift/context-menu регрессии проверяют исключение скрытых записей из действий. Отдельная регрессия на 1 000 строк ограничивает число созданных нативных views и находит изначально невидимую строку.

Настоящий NSTextView редактора SwiftUI-поля проверяется через Command+F, ввод RU/EN, очистку, Escape, Enter, сохранность фокуса, accessibility label/идентификаторы, состояния отсутствия совпадений и темы aqua/darkAqua при ширине 240/360 pt.

Команды:

```sh
swift test -c release -j 4 --force-resolved-versions --filter 'RecordingTitleSearchTests|RecordingSearchIntegrationTests|RecordingGroupsTests|RecordingGroupIntegrationTests|SidebarSelectionTests'
swift test -c release -j 4 --force-resolved-versions
swift build -c release -j 4 --force-resolved-versions
LOCALSCRIBE_SEARCH_BENCHMARK=1 swift test -c release -j 4 --force-resolved-versions --filter RecordingSearchPerformanceTests
```

Полный release-прогон: **407 XCTest — 171 Core, 143 UI/service, 93 worker/диаризации; 0 ошибок, 11 пропусков** (8 opt-in модельных/probe, 2 нативных DnD без зарегистрированной .app и 1 opt-in поисковый бенчмарк). Окончательный целевой прогон: **57 тестов, 0 ошибок, 2 DnD-пропуска**. Отдельный opt-in бенчмарк с нативным стрессом выполнен успешно без пропуска. Финальная `swift build -c release -j 4 --force-resolved-versions` завершилась успешно; новых предупреждений в коде поиска нет.

## Release-замеры

MacBookAir10,1, Apple M1, 16 GiB; macOS 27.0.1 (26A434), Apple Swift 6.4 (swiftlang-6.4.0.34.1), arm64. Использованы имеющиеся Metal-артефакты и разрешённый доступ SwiftPM к кэшам; чистая сборка Metal не выполнялась.

Синтетический корпус RU/EN/цифры: медиана 36–37 графем, p95 38–40; одинаковые префиксы, уникальные похожие слова, числовые токены. На каждом размере 16 прогревочных и 200 завершённых запросов, 1–3 слова. Подготовка fixtures/архива исключена. Замеры последовательные, без компиляции одновременно с поиском; окно для основных 200 запросов не монтируется. Публикация измеряется через barrier завершения, включая небольшой расход планирования наблюдателя, и не равна появлению кадра.

Первичный индекс: 15,1 / 159,1 / 734,6 мс на 1 000 / 10 000 / 50 000. Дополнительный RSS при построении: 2,3 / 19,3 / 101,4 MiB (включает аллокатор и временные структуры, не является точным размером удерживаемого индекса). Изменение RSS после 200 повторов, исключая 16 прогревочных: +96 KiB / 0 / +3,11 MiB. На основном корпусе 10 000 рост не наблюдался; небольшой прирост на 50 000 за один пакет не доказывает утечку или её отсутствие, для проверки длительной работы нужно отдельное наблюдение. Максимальный измеренный блок MainActor: 0,127 мс на 10 000 и 0,632 мс на 50 000. Отмена → idle включает доставку завершения на MainActor и является верхней оценкой реакции CPU-задачи.

В настоящем окне XCTest на 50 000 строк обработка нативного ввода занимала до 1,17 мс, фокус сохранялся. Дополнительный RSS окна — 90,9 MiB. Таймер MainActor показывал интервалы до 36,44 мс при параллельном worker; этот интервал включает SwiftUI/AppKit и планирование ОС, а не только применение поискового результата. Это ограниченная проверка отзывчивости, не подтверждение кадровой плавности через Instruments.

Исходный замер до интернирования слов и префиксов: p95 чистого поиска на 10 000 — 53,37 мс. Отдельный числовой профиль по типам запросов подтвердил повторные нечёткие вычисления и хэширование Unicode-префиксов. Оптимизация сократила итоговый p95 до 25,85 мс; debounce не добавлялся. Сверка индекса и matcher с независимым oracle выполнена после оптимизации.

CPU worker-фикстура работает отдельным процессом через настоящий WorkerSupervisor и JSONL, создаёт загрузку одного ядра, отменяется с ожиданием выхода. Это проверка конкуренции и UI, а не модельный ASR/LLM-прогон. Длинные названия и запросы не обрезаются; отменённые запросы не входят в 200 завершённых замеров. Архивный I/O при серии вводов — 0 по счётчику реального repository.

Нативный стресс обнаружил обычный VStack внутри ленивого списка: он создавал все строки группы и их mouse monitors. Прерванный диагностический прогон достиг 7,2 GiB footprint. Содержимое `RecordingGroupDropArea` заменено на LazyVStack; повторный стресс завершился, регрессия проверяет виртуализацию. Это изменение нужно для отзывчивости настоящего окна, независимо от скорости фонового поиска.
