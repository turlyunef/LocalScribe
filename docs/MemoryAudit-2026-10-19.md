# Проверка памяти и отмены — 19 октября 2026

Статус: **приёмка не пройдена**. Отмена загруженной Qwen3.5 воспроизводимо
завершает worker с `SIGSEGV`: 10 из 10 попыток. Это сбой завершения MLX,
а не доказательство утечки памяти. Полный объём исходной методики не закрыт;
таблица ниже отделяет выполненные проверки от оставшихся.
Отдельно Leaks воспроизвёл три небольших блока инициализации worker;
их стеки и размеры приведены ниже.

## Среда и воспроизводимость

Apple M1, 16 GiB RAM, macOS 27.0.1 (26A434), Xcode 27.0 (27A266a),
Swift 6.4, питание от сети. Исходный commit:
`fca1e97c2074da7a52897e1e31a263006e610810`.
Пакет и `.app` собраны существующими release-командами без изменения
исходников, каталога, entitlements и схемы подписи приложения.
Чистая сборка Metal не проверялась: использованы имеющиеся Metal-артефакты.
Проверены размеры и SHA-256 всех 63 файлов исходного комплекта
`asr / diarization / summary / tokenizer`: совпали с `models.lock.json`.
Во время измерений модели не скачивались, сборки не выполнялись.

Использованы разрешённые пользователем локальные синтетические фикстуры:
`mixed.wav` — 22,2435625 s, `three-hours.wav` — 10800 s.
Это технические проверки ресурсов, не WER/DER и не приёмка настоящей встречи.
Тестовые записи находятся только в `TestResults`, пользовательский архив
ими не пополнялся.

Локальные артефакты и точные команды:

## Воспроизводимый сбой отмены LLM

Во всех 10 попытках после первого `progress` и задержки 1 s worker успевал
загрузить модель и перейти к генерации. После EOF он отправлял `cancelled`,
но завершался сигналом 11 вместо ожидаемого кода 72. Группа процессов
исчезала; дескрипторы родителя оставались **5 до / 5 после**. Хэши checkpoints
не менялись.

В crash report одновременно зафиксированы:

- поток отмены: `Worker.terminateGroup → exit → __cxa_finalize_ranges →
  mlx::core::scheduler::Scheduler::~Scheduler → gpu::synchronize`;
- падающий поток: `Qwen35Model / TokenIterator.prepare → mlx_eval →
  CustomKernel::eval_gpu → unordered_map::find`, `EXC_BAD_ACCESS`, адрес `0x8`.

Это указывает на гонку между `exit`/деструкторами MLX и продолжающимся
inference. Место вызова — [Worker.terminateGroup](../Sources/LocalScribeWorker/Worker.swift).
Отфильтрованный стек без содержимого разговора:
[llm-cancel-crash.json](../TestResults/memory-audit-2026-10-19/llm-cancel-crash.json).

Серию можно воспроизвести на текущем standalone worker:

```sh
python3 TestResults/memory-audit-2026-10-19/repro_llm_cancel.py \
  --worker .build/out/Products/Release/LocalScribeWorker --count 10
```

Скрипт использует сохранённый технический reference из полного контрольного
прогона и создаёт новый временный каталог. `summary-parts` удаляются только
в этой копии, чтобы checkpoints не пропустили вычисления. SDK stderr
отбрасывается. Исправление приложения в рамках этого отчёта не применялось.

Контроль гипотезы: отдельная release-копия собрана из исходных worker sources
с единственной заменой `exit(code)` на `_exit(code)` в `terminateGroup`.
На ней **10/10** таких же отмен завершились кодом **72**, без SIGSEGV,
оставшихся процессов и роста FD родителя (**3 до / 3 после**).
Это подтверждает направление исправления; оно ещё не внесено в продукт.
Результат и команды:
[quick-exit-evaluation.json](../TestResults/memory-audit-2026-10-19/quick-exit-evaluation.json),
`prepare_probes.py --quick-exit`, `repro_llm_cancel.py`.

## Диагностика MLX и Instruments

Изолированные executable находятся в `probes/`. Один — копия release worker
с диагностической подписью, второй собран из копий текущих worker sources
с добавлением snapshots. Приложение и его helper не переподписывались для
подключения отладчика; запрет сети в worker сохранён.

MLX-опыт использует только первую реплику синтетической расшифровки,
чтобы сравнивать небольшие запросы. Он не измеряет длинный контекст встречи.
Snapshots делаются после загрузки, возврата запроса и освобождения локальных
ссылок контейнера, с `Stream.gpu.synchronize()`. Очистка кэша выполняется
только в отдельном опыте.

Во всех трёх процессах после загрузки `activeMemory = 5038045616` байт
(4,69 GiB). После первых трёх extraction-запросов активная память возвращалась
к этому же числу. После четвёртого временно оставалось ещё 16,4 / 28,7 / 19,4
MiB соответственно; после возврата summary во всех трёх процессах активная
память снижалась до **4016 байт**. Это не постоянное удержание весов/буферов
между завершёнными обработками.

| Процесс | Active после summary, байт | Cache после summary, байт |
| --- | ---: | ---: |
| 1 | 4016 | 268456314 |
| 2 | 4016 | 268447354 |
| 3 | 4016 | 269080958 |

Кэш около 256 MiB согласуется с установленным cache limit; этот предел
не является пределом памяти весов. Различие между активной памятью и кэшем
подтверждено для этого небольшого сценария, но не для многочасового LLM.
В отдельном опыте `clearCache()` снизил cache с **268671788 до 0 байт**,
при этом active остался **4016 байт**. Кэш не очищался в трёх основных
диагностических запусках.

Для записи с самого запуска использовался отдельный файловый вход команды
в диагностической копии worker: ожидание EOF отключалось только при
`--profile-command-file`. Это обход буферизации stdin в xctrace; в продукте
JSONL/EOF не менялись. Отмена проверялась исходным worker, отдельно от профиля.
Сетевой запрет и parent watchdog диагностической копии сохранены.

Графики [active/cache трёх процессов](../TestResults/memory-audit-2026-10-19/charts/mlx-runs.png)
и [отдельного clearCache-опыта](../TestResults/memory-audit-2026-10-19/charts/mlx-clear-cache.png)
строятся из `mlx-memory.json` с исходными метками snapshots.

## Достоверность замеров и ограничения

`processes.csv` содержит PID, PPID, PGID, RSS, physical footprint, FD и ошибки
доступа; `system.csv` — pressure, физическую память compressor, объём
сжатых страниц и swap. `marks.jsonl` задаёт фазы и границы циклов.
Сэмплирование — примерно раз в секунду: очень короткий процесс или пик между
замерами может быть пропущен. `maxResidentBytes` из worker приведён отдельно
от текущих показателей. Общие службы ANE/аудио не приписываются целиком
LocalScribe и не складываются с RSS worker.

macOS отказала в `proc_pid_rusage` для части системных служб. В поздних сериях
для них записан доступный через `ps` RSS; недоступные footprint/FD оставлены
пустыми с кодом ошибки. Их нельзя трактовать как нулевую память.

Сохранены также невалидные попытки измерителя: запуск подписанного
inherit-helper без sandbox-родителя, гонка собственного временного FD
сэмплера и тёплая короткая диаризация, закончившаяся до отмены. Они исключены
из 60 содержательных проверок и не объявлены дефектами LocalScribe.
Первый дополнительный ASR-resume прогон также исключён из ресурсного
сравнения: начальный замер FD попал между открытием двух CSV самим монитором,
а проверка объединённой расшифровки не учитывала каноническое переименование
ID в `Analysis.mergeParts`. Сырые данные сохранены в
`asr-resumption-invalid-checker/`; сценарий повторён после исправления
измерителя и проверки семантических полей реплик.
Отдельно сохранены первые профили Instruments без workload: один не
запустился из-за прав диагностической копии, другой ожидал stdin. В качестве
результатов используются только два trace с суффиксом `-valid`.

Release XCTest: **218**, ошибок **0**, ожидаемых модельных пропусков **2**.
Покрыты bounded channel, joins при отмене, stubborn child, pipe readers,
возобновление checkpoints, отмена установки и сохранение состояния микрофона
при приостановке фоновой обработки. Это не подтверждает TCC/микрофон,
профиль живых объектов GUI или качество моделей на настоящей встрече.

Общий критерий отсутствия необъяснённого остаточного роста на цикл пока
не подтверждён. Для полной приёмки необходимы оставшиеся объёмы таблицы,
после исправления воспроизводимого завершения LLM.

После всех опытов повторно совпали SHA 63 модельных файлов, 6 аудиофикстур,
каталога, lockfile и исходных бинарников. Подпись `.app` прошла проверку;
технических worker не осталось. Итоговая проверка:
[postconditions.json](../TestResults/memory-audit-2026-10-19/postconditions.json).
