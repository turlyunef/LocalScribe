# Ограничение очереди segmenter → embedder (R05)

18.10.2026. `PyannoteDiarizerActor.processClip` использует ограниченный
`DiarizationChannel<SpeakerSegmenterOutput>` вместо неограниченного `AsyncStream`.
Новых зависимостей нет. Изменения отслеживаемого SpeakerKit сохранены
в `ThirdParty/SpeakerKit/backpressure.patch`, применяемом после двух прежних патчей.

## Предел памяти и завершение

Ёмкость очереди по умолчанию — один output. `SpeakerSegmenterModel.predict`
и общий для Core ML/fake predictor метод `predictChunks` принимают асинхронный
`sendOutput`. Каждый segmenter worker ожидает отправку до следующего inference;
задачи на каждый блок не создаются. При S segmenter workers и E embedder workers
одновременно живы не больше `capacity + S + E` outputs, включая отправителей,
ожидающих места, и блоки внутри embedder. В worker LocalScribe S=E=1: максимум
три outputs. Количество блоков записи на этот предел не влияет.

Канал не отбрасывает элементы. После успешного producer очередь дренируется;
успех по-прежнему требует каждого ожидаемого индекса ровно один раз, включая
успешные блоки тишины. Ошибка или отмена очищает очередь и пробуждает обе стороны
до join дочерних задач. Отмена отдельного ожидания удаляет только его continuation:
при ошибке predictor отменённые соседние отправители не закрывают consumers
раньше, чем исходная ошибка достигнет владельца внешней группы. Регистрация,
доставка и отмена continuation синхронизированы `Mutex`; отмена до регистрации
тоже учитывается. Отдельных фоновых задач для teardown нет.

Предварительное разбиение входного PCM на массивы не изменялось: этот предел
относится к outputs и удерживаемым ими ML-массивам, а не ко всей памяти анализа.
`segmenterTime` измеряет время producer целиком и теперь включает ожидание места;
это не чистое время Core ML. Глобальная кластеризация, stride, содержимое блоков,
реальная `waveformLength`, хвостовое дополнение и маски embedder сохранены.

Версия новых заданий — `1.0.0-audio2-asr5-live1-diarization4-summary11`.
Старые задания сохраняют свою версию и fingerprint; результаты автоматически
не мигрируют. ASR-контрольные точки и прежний active run сохраняются при сбое.

## Тесты и воспроизведение

`BackpressureTests` проверяет 512 блоков с быстрым fake predictor на настоящем
планировщике `predictChunks` и медленным embedder (2 ms на блок). Каждый output
содержит отдельный ML-массив 1 MiB с записанными значениями; provider считает
создание и освобождение outputs без их удержания тестом. Проверяются все индексы
ровно один раз, данные массива, stride, длина хвоста, предел живых outputs
и освобождение всех outputs после завершения.

Дополнительные проверки: ошибка embedder с заполненной очередью, отмена родителя
при заблокированной отправке, ошибка predictor при нескольких заблокированных
соседних отправителях с сохранением исходного типа ошибки, дренирование очереди,
повторное закрытие, отмена idle receive и отправок до/во время регистрации.
Сценарий отмены send повторяется 200 раз. Прежние тесты R01 продолжают проверять
отсутствие публикации частичной диаризации и сохранение прежнего результата.

```sh
swift test -c release -j 4 --force-resolved-versions --filter BackpressureTests
```

Полный прогон с имеющимися локальными моделями и регрессионным WAV:

```sh
LOCALSCRIBE_DIARIZATION_FIXTURE_WAV=/absolute/path/to/regression.wav \
LOCALSCRIBE_DIARIZATION_FIXTURE_MODELS=/absolute/path/to/diarization \
swift test -c release -j 4 --force-resolved-versions
```

Результат: 156 XCTest (85 Core, 44 UI/service, 27 диаризации), 0 ошибок,
0 пропусков. В 27 входят семь новых тестов backpressure. Сборка использовала
имеющиеся Metal-артефакты; чистая сборка MLX без них не проверялась.

Для отдельного измерения процесса XCTest после сборки:

```sh
bin=$(swift build -c release --show-bin-path)
/usr/bin/time -l xcrun xctest \
  -XCTest LocalScribeDiarizationTests.BackpressureTests/testFastSegmenterSlowEmbedderBoundsLiveOutputsWithoutDroppingIndices \
  "$bin/LocalScribeDiarizationTests.xctest"
```

Замер отдельного процесса на M1/16 GB, установленная macOS 27.0.1:

| Передача | S / E / ёмкость | Пик живых outputs | Пик RSS по выборке, байт | Время 512 блоков |
| --- | --- | --- | --- | --- |
| Ограниченный канал | 1 / 1 / 1 | 3 | 38 158 336 | 1,578 s |
| Ограниченный канал | 4 / 2 / 3 | 9 | 52 133 888 | 0,782 s |
| Прежний неограниченный stream | 1 / 1 / ∞ | 499 | 568 885 248 | 1,565 s |
| Прежний неограниченный stream | 4 / 2 / ∞ | 500 | 576 831 488 | 0,770 s |

Максимум RSS процесса по `/usr/bin/time -l` (обе конфигурации в одном процессе):
53 444 608 байт с каналом против 578 125 824 байт с неограниченным stream.
Для сравнения временно использован адаптер прежнего `AsyncStream.makeStream`
за тем же async send/receive интерфейсом, без изменения fake payload/задержки
embedder; после замера исходник канала восстановлен. Регрессионный тест
ожидаемо отклонил неограниченный вариант по обоим пределам живых outputs;
все индексы при этом были обработаны. RSS по выборке считывается при создании
outputs через `task_info`; kernel maximum измерен отдельно для всего процесса.
Это одиночные тёплые прогоны с задержкой fake embedder, не оценка скорости
Core ML. Producer и consumers остаются независимыми структурированными задачами;
реальная пропускная способность моделей требует отдельного измерения.

## Качество и границы проверки

Настоящий собранный worker обработал локальный регрессионный WAV 37,9 s.
Все пять опубликованных интервалов (границы и ID голосов) точно совпали
с сохранённым результатом до R05: два участника, A–B–A, последний интервал
заканчивается на 37232 ms. SHA исходника, ASR, manifest и прежнего результата
не изменились. Реальные модели также прошли тест границ stride и короткого хвоста.
Частные аудио, текст, веса, логи и результаты прогонов не добавлены в Git.

Абсолютный DER не рассчитан: размеченного эталона нет. Точное совпадение интервалов
подтверждает отсутствие регрессии на этом примере, но не заменяет DER и проверку
длинных реальных встреч по `MacAcceptance.md`. RSS XCTest с fake outputs не равен
памяти всей системы или реальной модели; учитываются также память моделей,
Core ML/ANE-служб, входной PCM, embeddings для глобальной кластеризации и swap.
