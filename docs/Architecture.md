# Реализация и воспроизводимость

Архивные операции GUI выполняет последовательный `RecordingCoordinator` вне MainActor. Manifest сохраняется атомарно отдельно от вспомогательного индекса; список хранится в снимке coordinator, а восстановление читает архив одним проходом и один раз записывает индекс. Ошибка индекса не мешает чтению и восстановлению manifests. Подробности и замеры на 1000 записях — [RepositoryPerformance.md](RepositoryPerformance.md).

Swift Package содержит LocalScribe (SwiftUI/AppKit), LocalScribeCore (контракты/хранение/экспорт), LocalScribeWorker (WhisperKit + SpeakerKit OSS + MLXLLM) и LocalScribeModelService (XPC-загрузка только закреплённых модельных файлов).

GUI и worker имеют App Sandbox **без** network.client. Worker наследует sandbox, проверяет запрет исходящего подключения до загрузки SDK и создаёт отдельную группу процессов для отмены FFmpeg вместе с собой. У standalone developer probe используется дополнительный deny-network профиль; sandbox_init не применяется повторно в поставляемом helper. Только XPC-загрузчик имеет network.client. Он не получает транскрипцию, аудио, пути архива или доступ к папке моделей. В ответ на ID профиля и индекс файла из встроенного каталога он передаёт открытый дескриптор скачанного файла. GUI потоково копирует его в собственную .partial-папку и проверяет SHA-256. Передача security-scoped bookmark между разными ad-hoc идентичностями на этом Mac не прошла проверку; использование дескриптора устраняет необходимость делить доступ к данным.

Причина выделения загрузчика — фактический отказ macOS при попытке повторно применить профиль к наследующему App Sandbox процессу. Обработка остаётся в одном последовательном worker, а не в XPC/HTTP inference-сервисах. XPC-процесс не содержит моделей и не выполняет анализ.

JSONL protocol v1: одна команда через stdin, события через stdout, stderr непрерывно дренируется и не сохраняется приложением. SDK stdout перенаправлен в stderr. Большие результаты — атомарные JSON-файлы в runs. GUI проверяет тип, диапазоны времени, fingerprint и ссылки перед переключением activeRunId. RunInfo закрепляет SHA исходника, hash модельных revisions, pipeline/prompt revision, язык и время создания. Токеновые/ресурсные проверки сохраняются без текста в llm-audit.json и metrics-*.json.

Повторное чтение результата проходит через `RecordingRepository.results`: проверяются UUID и schemaVersion manifest/run, привязка к SHA исходника, fingerprint и таймкоды расшифровки, поля и ссылки итогов. Повреждённый конечный JSON не заменяется молча контрольной точкой. Ошибка изолирует результат выбранного run, показывается пользователю и не меняет файлы или activeRunId. Для незавершённого микрофонного источника preview проверяет capture-run и ограниченные live-контрольные точки в шкале захвата; окончательные артефакты открываются только после привязки к исходнику. Индексы ASR и длительности ограничиваются до арифметики.

Новые `RunInfo` сохраняют `manualEdits: false`, ручные редакции — `true`; поле не входит в fingerprint. Только ручная редакция допускает пункт без evidence, а непустые ссылки проверяются всегда. Для старых редакций без поля используется совместимость: ссылка на исходный run с тем же fingerprint/SHA и отсутствие машинных ASR/диаризационных артефактов и следов генерации итогов (`summary-parts`, `llm-audit.json`). Одной ссылки `transcriptSourceRunID` недостаточно. Новое автоматическое пересоздание итогов всегда получает `manualEdits: false`.

Каталог содержит альтернативы по ролям `asr` и `summary`; каждый профиль хранится отдельно в `models/<id>`. `models/selection.json` сохраняет время успешной установки и выбор по ролям. При первом запуске существующие папки исходных моделей проверяются и подхватываются без переименования. Варианты Whisper используют соответствующий токенизатор. `RunInfo.modelIDs` фиксирует выбранные профили при создании задания; старые задания без этого поля используют исходные имена папок. Fingerprint альтернатив включает ID, ревизию и SHA файлов, чтобы разные модели из одной ревизии репозитория не разделяли контрольные точки. Исходный комплект сохраняет прежний fingerprint. Установка и смена выбора не меняют manifests и не ставят ожидающие записи в очередь. «Продолжить» проверяет закреплённые ID, hash ревизий/файлов и SHA-256 установленных моделей вне главного актора; текущий выбор для новых заданий не влияет на pending run. Отсутствующий или несовместимый комплект, повреждённый run и изменение версии pipeline блокируют продолжение с указанием причины, сохраняя run и контрольные точки. Новый run с текущим выбором создаётся отдельным действием «Обработать заново». При явном пересоздании итогов копия прежней расшифровки получает fingerprint нового задания, а `transcriptSourceRunID` указывает источник; оригинальный результат не изменяется.

XPC-загрузчик передаёт полученные байты через `URLSessionDownloadDelegate`; сообщения привязаны к уникальному запросу файла. GUI суммирует их с проверенными файлами текущей модели, показывает общий объём и список файлов. Возобновление пропускает уже проверенные файлы `.partial`; публикация и выбор новой модели происходят только после проверки всего комплекта. Оценка пригодности Mac использует архитектуру, поддержку Metal, физическую RAM и `recommendedMaxWorkingSetSize`; требования в каталоге — ориентировочные, не результаты измерений.

Установщик сверяет размер открытого regular-file/FD с каталогом через `fstat` до создания файла назначения. Потоковое копирование, включая растущий источник, читает не больше каталожного размера плюс один проверочный байт и не записывает превышение. Прямой HTTP-загрузчик и XPC получают `expectedSize` из закреплённого каталога: каждый download callback проверяет фактически записанные байты до ограничения частоты сообщений прогресса и отменяет задачу при превышении, независимо от `Content-Length`. Сетевой overshoot ограничен доставкой callback и остановкой URLSession; временный файл удаляется при ошибке. Конечные проверки размера и SHA-256 сохраняются; отказ удаляет только незавершённый файл, сохраняя старую модель и проверенные файлы `.partial`.

ASR сохраняет части до 5 минут; внутри выбирает основные окна не длиннее 28 секунд у пауз с контекстом по секунде с обеих сторон: весь вход Whisper не превышает 30 секунд. Язык определяется заново. Тишина не удаляется. Word-midpoint retention привязывает перекрытия к исходным интервалам; точность первых слов окна требует контроля на эталоне. Цифровая тишина пропускается, noSpeech/logprob/repetition используются для фильтров и неопределённости. Порог выбора пауз не является детектором пригодности тихой речи.

Если перед первым распознанным словом остаётся заметный интервал со звуком либо окно вернуло пустой текст, ASR один раз повторяет распознавание с расширенным контекстом до 30 секунд. Из повтора берётся только отсутствующее начало, со словами и таймкодами модели; уже полученный текст сохраняется. Энергия звука служит только основанием для повтора, а не подтверждением речи. Невосстановленное начало вызывает предупреждение. `windowClipTime = 0` отключает пропуск последней секунды в SDK. Общий SpeechRecognizer применяет эти правила и к фоновым CAF, и к завершённому оригиналу. Версия `asr5` отделяет новые контрольные точки от прежних; подробности проверки — [ASRPrefixFix.md](ASRPrefixFix.md).

SpeakerKit получает всю нормализованную запись одним глобальным проходом. Метки перенумеровываются по первому появлению, сопоставление идёт на уровне слов, при нескольких активных голосах/слабом пересечении участник не угадывается. Не выполняется независимая кластеризация пятиминутных частей.

Worker использует отслеживаемый снимок SpeakerKit 1.1.1 (`LocalScribeSpeakerKit`)
с отражающим дополнением неполного 30-секундного входа вместо нулей.
Реальная длина блока и исходная шкала времени сохраняются, дополнение существует
только во входе модели. Публикуемые интервалы ограничиваются длительностью
оригинала; пустые интервалы и интервалы за его концом отбрасываются.
Отражающее дополнение введено в `diarization2`; подробности и границы проверки —
[DiarizationTailFix.md](DiarizationTailFix.md).

В `diarization3` ошибки segmenter и embedder выходят через throwing task groups.
Каждый ожидаемый блок должен успешно пройти оба этапа ровно один раз; корректный
блок без речи учитывается даже с пустыми embeddings. При ошибке stream закрывается
до ожидания дочерних задач, соседние задачи отменяются, незавершённая диаризация
не доходит до кластеризации и публикации `transcript.json`. ASR и прежний active run
сохраняются. Inference выполняется в структуре задачи вызывающего кода, поэтому
отмена достигает producer и consumers. Новые задания получают другой fingerprint;
старые результаты остаются читаемыми и автоматически не пересчитываются.

В `diarization4` передача segmenter → embedder идёт через ограниченный канал
с приостановкой producer: один output в очереди плюс по одному на каждый
занятый segmenter/embedder worker (в LocalScribe всего не больше трёх).
Каждый индекс сохраняется, успешное завершение дренирует очередь, ошибка
или отмена освобождает outputs и будит ожидающих до join дочерних задач.
Отмена sender в группе segmenter не закрывает канал преждевременно:
исходная ошибка prediction сначала доходит до владельца группы.
Глобальная кластеризация и исходная шкала времени сохранены.
Замеры и ограничения проверки — [DiarizationBackpressure.md](DiarizationBackpressure.md).

LLM: текстовый Qwen35Model, без visual tower; thinking=false через chat template с проверкой фактически токенизированного суффикса. До каждого запроса считается вход и резерв ответа, общий предел 8192.

Строки источника, их token counts и индекс ID готовятся один раз на запуск summary, включая возобновление. Проверки решений и задач используют эти данные для поздних групп без повторной токенизации реплик; отвергнутый пункт сразу пропускает подготовку хвоста. Текст prompts, порядок и границы групп, fingerprints и версии summary13/prompt-v13 сохранены. Подсчёт полных chat prompts для проверки бюджета и число необходимых LLM-проверок не меняются.

В summary13/prompt-v13 проверки оснований и поздних уточнений планируют готовые chat prompts через тот же tokenizer/template, что и генерация. В бюджет 8192 входят system, кандидат, источник, корректирующая инструкция второй попытки и 512 токенов ответа; обе попытки считаются отдельно. Соседние реплики перекрываются, а не помещающаяся целиком реплика делится на адресуемые диапазоны символов с исходными ID и таймкодами. Ни одно основание или поздняя реплика не отбрасывается; для уточнений проверяется каждая пара страниц исходного и позднего контекста. Цитата проверяется именно в показанном фрагменте. Локальное отсутствие поддержки не отменяет положительный вердикт другой страницы. Если контекст разделён, пункт сохраняется с неопределённостью, в том числе при отсутствии достаточной поддержки на отдельных страницах; отказ разрешён при полном контексте. Противоречивые уточнения и неопределённые источники не отменяют пункт. Применение уточнения использует проверенный кандидат и адресованную точную цитату, не собирая заново весь неограниченный контекст. Изменение версии отделяет checkpoints от старого алгоритма; формат конечных итогов не меняется.

В summary12/prompt-v12 каждый открытый вопрос из реестра проверяется по последующей речи до явного разрешения или конца встречи, в том числе за пределами перекрытия частей extraction. Закрытие требует ответа или явного закрытия именно этого вопроса, дословной цитаты и ID последующей реплики. Молчание и ответы на другие вопросы его не закрывают; неоднозначный ответ сохраняет вопрос с неопределённостью и ссылкой на уточнение. Неопределённая исходная реплика не может подтвердить закрытие. Вердикты сохраняются атомарно в `summary-parts/resolve-question-<вопрос>-<часть>.json`; fingerprint включает версию prompt, всю расшифровку, язык, вопрос, исходный контекст и проверяемую часть. При возобновлении цитата и ID повторно проверяются; несовместимые или повреждённые checkpoints пересчитываются. Формат конечного Summary не меняется.

В summary11 каждый раздел извлекается отдельным проходом для каждого встречающегося языка. Ответ модели содержит только целевой именованный массив; остальные массивы контракта Summary добавляются в коде, а отсутствие целевого поля считается ошибкой формата. Это не меняет формат сохранённых итогов. Попадание реплики в обзор не считается охватом решений, задач или вопросов. Каждый проход видит хронологический контекст на всех языках, а соседние части перекрываются до двух реплик в пределах токенового бюджета. Частичные результаты сохраняются отдельно по разделу и языку. Факты и статусы участников относятся к обзору; их подтверждение не становится решением, а выполненная в разговоре просьба не становится будущей задачей. Дополнительные проходы увеличивают число запросов модели; скорость на длинных встречах требует отдельного замера. Темы сводятся иерархически; полный реестр задач не заменяется кратким изложением.

Каждое решение/задача проверяется коротким отдельным вердиктом с дословной цитатой из основания и соседними репликами; кандидат не переписывается заново. При поиске цитаты допускается только замена начертания кавычек/апострофов; возвращаемая цитата восстанавливается из исходной реплики, слова и ID источника должны совпадать. Сам кандидат должен называть конкретное действие: короткое подтверждение из исходника может служить основанием, но не становится отдельным пунктом без названного действия. Если проверка использует соседнюю реплику с конкретным предложением, её ID добавляется в основания вместе с исходным подтверждением, с сохранением неопределённости. Неизвестные ответственные и сроки не препятствуют сохранению подтверждённого действия. Проверяются все последующие реплики для отмен и уточнений. Удаление требует явной отмены с цитатой; отсутствие поручения в позднем фрагменте не считается отменой. После этого точные повторы с одинаковыми владельцем и сроком объединяют ссылки; разные владельцы/сроки остаются отдельными. Невалидный/усечённый JSON не фиксируется как итог; разрешена одна корректирующая попытка. Это алгоритм, а не гарантия смысловой безошибочности модели.

Файловые операции записи микрофона вынесены на последовательную очередь. Callback берёт буфер из ограниченного пула и копирует сэмплы; готовые десятисекундные CAF закрываются и синхронизируются вне callback. Частично закрытый фрагмент не включается в восстановление. После сборки оригинала проверяются число сэмплов и hash. При фоновом ASR фрагменты сохраняются до проверенного присоединения контрольных точек к оригиналу и выхода worker; без фонового ASR удаляются после сборки. Состояние очереди и manifest меняет только GUI; worker не перезаписывает manifest.

Разработческие --self-check/--self-check-download проверяют настоящую подписанную цепочку и XPC в diagnostics, не в пользовательском архиве. --trace-model-output принимается только для sourceType=technical-probe и никогда не передаётся GUI. Эти файлы остаются локальными в TestResults и исключены из исходного/пользовательского дистрибутива.

Сборка закреплена Package.resolved и models.lock.json, FFmpeg source SHA-256 проверяется перед configure. build_app.sh копирует Metal/resource bundles и подписывает вложенные helper/XPC/tools перед внешним bundle. MLX дополнительно получает `Contents/Helpers/mlx.metallib` рядом с worker: в helper `Bundle.main` отличается от GUI, поэтому одного bundle в Contents/Resources недостаточно. Metal-библиотека отдельно подписывается как вложенный code object; иначе strict verification отклоняет .app. Для повторения релизной среды нужен указанный Xcode/Metal Toolchain; более ранний toolchain не заявляется как проверенный.

Загрузку результата при смене выбранной записи сопровождает немедленная очистка старого представления; асинхронный ответ применяется только к тому же UUID/signature. Manifest с UUID, не совпадающим с каталогом, исключается из списка/восстановления, чтобы повреждённая запись не перезаписала соседнюю.

Редактор результатов работает с отдельным черновиком: отмена не пишет файлы. При сохранении GUI проверяет исходную версию задания, fingerprint, структуру реплик и основания итогов, затем атомарно публикует новую activeRunId только после записи полного комплекта JSON в новый run. Предыдущий run и контрольные точки worker сохраняются. Редактор позволяет удалять реплики; удаление реплики с основаниями в итогах требует подтверждения и убирает ссылки на неё из всех разделов. Ручные пункты итогов могут сохраняться без оснований; автоматические итоги по-прежнему требуют ссылки на источник. Если остаются другие основания, ответственный и срок проверяются по ним, неподтверждённые поля очищаются. При удалении последнего основания поля пункта сохраняются как ручные. Правки оставшихся реплик не меняют ID, таймкоды и участников; устаревшие word timings изменённых реплик удаляются. Итоги автоматически не пересоздаются. Явное пересоздание итогов использует исправленную расшифровку и пропускает все аудио/ASR-этапы при наличии проверенного diarized transcript. Фоновый импорт не переключает запись, пока открыт редактор.

Фоновое распознавание во время записи, отдельные состояния, дисковая очередь и проверка присоединения к оригиналу описаны в [LiveCapture.md](LiveCapture.md). Новая запись не прерывает текущую обработку; один worker последовательно завершает старые задания.
