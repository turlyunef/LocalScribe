## Полные пропуски, стыки и доступность контекста — сессия 4

`scripts/probe_asr_boundaries.py` и opt-in `ASRBoundaryProbeTests` сравнивают
первую паузу с offline внешними частями 300 с и live частями 30 с на одинаковом
раскрытом PCM. Расписание восстанавливается от настоящих начал частей;
выбираются целые окна, пересекающие те же ручные интервалы. Это контроль
режимов, а не полный прогон всей встречи или приёмка физического микрофона.
Подробности — `TestResults/asr-boundaries-session4-20261022/REPRODUCE.md`.

Live-replay сначала закрывает 10-секундные CAF, проверяет их seal/SHA/PCM и
собирает только входы текущей части. Каждое фактическое обращение к модели
сверяется с тем же исходным PCM; `originMs` и `availableEndMs` ограничивают
контекст. Сэмплы за этим пределом, фиктивная начальная тишина и открытые
`.partial.caf` не используются. Штатный worker/EOF/resume проверяется отдельно
через `probe_live_capture.py`; replay не выдаётся за checkpoint приложения.

По три ограниченных новых контекста на цель сохраняют raw/mapped гипотезы
отдельно. Выборочная разметка, шум и неизвестные маски прежние; итоговый
источник 86996041 не используется. Одинаковые входы между offline/live
сопоставляются отдельно: вариативность/fallback SDK не приписываются целиком
границе внешней части. Пересечение словом шума и похожий текст на стыке —
диагностика; автоматического удаления, вставки или forced alignment нет.

```sh
python3 scripts/probe_asr_boundaries.py \
  --output TestResults/asr-boundaries-session4-NEW/experiment-r2 \
  --prepare-from TestResults/asr-settings-session3-20261021-r1 \
  --variants plan offline live retries
```

Подготовка требует нового каталога. Модели закрепляются по сохранённому run,
полные SHA проверяются до/после, сеть запрещается до загрузки, SDK-вывод
отбрасывается. Детальные результаты, принятые/отклонённые компоненты и
окончательная кандидатная политика — в [ASRExperimentStatus.md](ASRExperimentStatus.md).

## Отдельные настройки декодера — сессия 3

`scripts/probe_asr_settings.py` и opt-in `ASRSettingsProbeTests` проверяют
настройки поверх выбранного A, без изменения production. Входы — полный PCM
раскрытых записей; окна восстанавливаются первой паузой от реальных начал
300-секундных частей. Выбираются окна, пересекающие прежнюю ручную разметку.
Свежий baseline сохраняет primary/prefix-вызовы; все варианты получают те же
срезы и границы принадлежности. Повторы начала по новой гипотезе здесь не
перепланируются: это изолированная проверка декодера, не интеграционная приёмка.

Факторы запускаются отдельно: ru с предварительным аудио LID и возвратом
к autodetect для других языков; каждый из SDK-порогов noSpeech/logprob/
compression; короткий `promptTokens`. Подсказка токенизируется закреплённым
`WhisperTokenizer.encode`, BOS/EOS исключаются так же, как в SDK; проверяются
обратное декодирование и предел 64 текстовых токенов. Имена из неподтверждённой
расшифровки и термины итогового отложенного набора не используются.

Сырые `TranscriptionResult` и фактические опции каждого вызова сохраняются
только в техническом TestResults. Replay сохранения неопределённого текста
сравнивает отсутствие разрушительного app-фильтра с исходным mapper. Удалённый
самим SDK текст replay восстановить не может. Дополнительный `retry` разрешает
один новый контекст до 30 с перед удалением/заглушкой, исключает уже выполненный
вход и сохраняет обе гипотезы отдельно; отсутствие подходящих целей — допустимый
результат, а не доказательство качества повторов.

Число дополнительных LID и их wall time учитываются отдельно от transcribe:
публичный `detectLangauge(audioArray:)` закреплённого SDK выполняет свой encoder.
`sdkReportedFallbacks` остаётся необработанным полем SDK, не точным числом
температурных попыток. Загрузка модели и thermal state сохраняются отдельно.
Близкие результаты требуют повторов; исторические A/C не заменяют свежий
baseline. WER речи, ошибки на nonSpeech, маски и синтетический script-WER
приводятся раздельно. Модели/PCM проверяются полными SHA до и после, сеть
запрещается до загрузки; SDK stdout/stderr отбрасываются.

Артефакты: `TestResults/asr-settings-session3-20261021-r1`; порядок,
параметры и исходники — `pre-inference-freeze.json`, `settings-plan.json`,
`code-freeze.json`, `source-snapshot/`, `sdk-source-snapshot/`.
Команды и ограничения — `REPRODUCE.md`; решения после оценки — в
[ASRExperimentStatus.md](ASRExperimentStatus.md).

## Выборочный контроль по замороженному C — сессия 1

Режим `--context-from-baseline` повторно использует побайтные копии A/C из
успешной полной матрицы. Новые основные распознавания и повторы начала не
выполняются. Это фиксированная экспериментальная гипотеза, не возобновление
production checkpoints. `input.json.codeHash` относится к историческим A/C;
`probeCodeHash`, `environment.json` и `source-snapshot` закрепляют новый стенд.
Время A/C историческое; новые вызовы, загрузка и SDK-времена лежат отдельно
в `E/metrics-asr.json`, число вызовов — в `E/selective-info.json`.

```sh
python3 scripts/probe_asr_matrix.py \
  --context-from-baseline TestResults/asr-matrix-india-20261020-local \
  --recording '/Users/eugene/Library/Containers/local.localscribe.mac/Data/Library/Application Support/LocalScribe/recordings/1943E39F-EA0D-45D0-BCC5-B66B4AB6C8BA' \
  --output TestResults/asr-control-session1-NEW
```

Каталог назначения должен отсутствовать. `--prepare-only` проверяет модели,
декодер и план, создаёт аудио и пустой эталон без загрузки Whisper/inference.
Полный режим сначала выполняет ту же подготовку, затем только контекстные
вызовы. SwiftPM сам определяет путь XCTest; запускать с очищенным окружением
по инструкции ASRContinuation. Для Core ML могут требоваться системные кэши
вне файловой песочницы; сам процесс probe запрещает сеть до загрузки моделей.

Полный PCM сохраняется. `frozen-plan.json` восстанавливает все окна от начала
реальных внешних частей 0/300000/600000 мс тем же `Analysis`, чей SHA сверяется
с исходным стендом. Проверяются длительность, непрерывные внешние границы,
совпадение склейки C/parts с C/transcript, агрегаты основных окон/входов,
тишина, опции декодера, закреплённый run и полные SHA ASR/токенизатора.
Выбираются только реальные окна и цели, пересекающие заранее заданные
158000–179000, 365000–423000 и 567000–626000 мс. Планировщик целей и
`asr-word-repair-v1` не перенастраиваются. Отсутствие цели тоже сохраняется;
ручной принудительный повтор Figma не добавляется после просмотра результата.

Исторический C не сохранял пооконную историю повторов начала. Поэтому новый
режим консервативно исключает **все возможные** входы восстановления начала,
даже если неизвестно, использовались ли они. Это явно записано в
`prefixContextPolicy`; режим не выдаётся за точное воспроизведение свежего E.
Параметры и границы основных окон восстановлены точно; история вызовов C
не выдумывается. Бюджет v1 остаётся прежним: до трёх целей на окно, цель до
20 с, контекст до 30 с, без рекурсии. Одинаковые соседние контексты делят вызов.

`LISTEN-FIRST.md` содержит только аудио и инструкции. `reference.template.json`
пуст и не подтверждён. Три основные копии — в `review-audio`, точные единицы
разметки — в `annotation-audio`, соседнее аудио ±2 с — в `listening-context`.
Если цель пересекает край основного фрагмента, разметка расширяется до полной
цели: таймкоды остаются в шкале встречи. Пустой эталон разбит на
непересекающиеся цели и остатки, чтобы все четыре гипотезы оценивались на
одинаковых единицах. Соседний контекст слушать можно, слова из него в целевой
интервал не переносить. Подтверждение шума, обрезанных слов и `verifiedBy`
следует общим правилам ниже.

Автоматические тексты хранятся отдельно в `control-comparison.md/json` и
`context-review.md`. На целой цели сравниваются A, C, весь повтор и точечное
предложение; вне целей обе экспериментальные гипотезы равны C. Это набор
локальных оценочных единиц, **не** новый склеенный Transcript. Принадлежность
текста предложения цели сохраняется после снятия word timings. Частичное
пересечение новой разметкой цели явно помечается и не входит в общую оценку
четырёх гипотез: предложение без word timings нельзя молча нарезать.

После ручной разметки скопировать шаблон в `reference.reviewed.json`, заполнить
его и пересчитать отчёты без inference:

```sh
python3 scripts/probe_asr_matrix.py \
  --output TestResults/asr-control-session1-20261020 --report-only \
  --reference TestResults/asr-control-session1-20261020/reference.reviewed.json
```

Текущий статус, фактические проверки, SHA и ограничения —
[ASRExperimentStatus.md](ASRExperimentStatus.md). До ручной оценки WER равен
`null`; ни baseline, ни повтор, ни правка не объявляются победителями.

## Ответы человека на целые аудиофрагменты

Если пользователь прислал текст целого клипа вместо разметки отдельных целей,
использовать `scripts/score_asr_control.py`. Он проверяет полное непрерывное
объединение заранее замороженных единиц гипотез, сохраняет принадлежность
предложений целям и сравнивает A/C/повтор/v1 на одних целых интервалах. Эталон
по словам ASR не выравнивается и не нарезается автоматически. Новый Transcript
не создаётся, исходная папка контроля не перезаписывается, inference отсутствует.

```sh
python3 scripts/score_asr_control.py \
  --source TestResults/asr-control-session1-20261020 \
  --reference TestResults/asr-control-session2-20261020/reference.user-verbatim.json \
  --output TestResults/asr-control-session2-NEW
```

Ответы сохраняются дословно с `verifiedBy`, SHA исходника и копий аудио.
Неразборчивые слова и смех без ручных временных границ явно исключают целый
клип из строгого WER (`strictScoringEligible=false`), оставаясь в полном ответе
и качественном отчёте. Метки нельзя считать лексическими словами или
подтверждённым nonSpeech. Старый `--report-only` не предназначен для передачи
таких меток в качестве полностью разобранного текста.

Результат: `scores.json`, `full-comparison.md`, `alignments.tsv`,
`reference.user-verbatim.json`, `provenance.json` и снимок оценщика. Строгий
WER может охватывать меньше фрагментов, чем число полученных ответов;
покрытие и исключения показаны явно. Технические обозначения, междометия,
повторы и написание имён не исправляются задним числом ради WER.

## Оценка после точного уточнения неизвестных участков

Если человек уточнил слово либо дал полные интервалы смеха/неразборчивой
речи, сохранять новую версию эталона с происхождением изменений. Исходный
ответ, прежний отчёт и модельные гипотезы не перезаписывать.

```sh
python3 scripts/score_asr_control_masks.py \
  --source TestResults/asr-control-session1-20261020 \
  --reference TestResults/asr-control-session2-masked-20261020/reference.user-refined.json \
  --output TestResults/asr-control-session2-masked-NEW
```

`verifiedMasks` связывает каждый оставшийся маркер с полным подтверждённым
интервалом, видом события и `verifiedBy`. Известные тексты между маркерами
относятся к соответствующим интервалам человека, а гипотезы — по исходным
SDK midpoint. Выравнивание начинается заново в каждом известном интервале:
слово за неизвестной областью не совпадает бесплатно с эталоном до неё.
Неразборчивую многоголосую речь нельзя считать тишиной или шумом; слова
модели внутри масок сохраняются в диагностике, но не становятся эталоном.

Это WER известной речи с масками. Покрытие, неизвестная длительность,
пересечения границ и segment-midpoint fallback приводятся отдельно.
Пограничная ошибка тайминга может влиять на WER, даже если слово есть в
полном ASR. Маски не удаляют ничего из сохранённых Transcript или production.
Неизменённый proposed должен точно совпадать с original; если маска
пересекает цель с изменённым текстом без word timings, оценщик отказывается
вместо выдуманного выравнивания. При отсутствии известных слов WER равен null.

## Исходная полная матрица

Стенд от 20.10.2026 отделяет влияние границ окон от восстановления внутренних
пропусков. Production по-прежнему использует `asr7`: первая пауза, восстановление
начала, без локальных повторов внутренних пропусков/хвоста. Настройки декодера,
фильтры, языковая стратегия, каталог моделей и формат архива не изменены.
`pipelineVersion` не повышается: экспериментальные варианты вызываются только
явным техническим тестом и не публикуются в пользовательский архив.

| Вариант | Граница | Внутренние пропуски/хвост |
| --- | --- | --- |
| A | Первая пауза, production default | Без повторов |
| B | Первая пауза | Один повтор на промежуток |
| C | Последняя завершённая пауза после 14 с | Без повторов |
| D | Последняя завершённая пауза после 14 с | Один повтор на промежуток |

Поздняя граница и энергетическая эвристика повторов с контекстом по 250 мс
восстановлены из `asr6`. Повтор начала с контекстом до 30 с включён у всех.
Повтор пропуска добавляет только слова из отсутствующего интервала; уже
распознанные слова не заменяются. Энергия не доказывает наличие речи.

## Запуск

Нужны локальные модели закреплённого run, штатные FFmpeg/ffprobe и Xcode с
Metal Toolchain для сборки всего пакета. Модели не скачиваются. Скрипт работает
с mono-входом; подготовку противофазного стерео он намеренно не имитирует.
Команды выполняются из корня репозитория:

```sh
swift test -c release -j 4 --force-resolved-versions
python3 -m unittest discover -s scripts/tests -p 'test_probe_asr_matrix.py' -v
python3 scripts/probe_asr_matrix.py \
  --recording '/absolute/path/to/archive/recordings/UUID' \
  --reference-run 'FROZEN-RUN-UUID' \
  --models '/absolute/path/to/archive/models' \
  --tools '/absolute/path/to/Vendor/ffmpeg-8.0.1' \
  --output 'TestResults/asr-matrix-fresh'
```

Без `--reference-run` используется `activeRunId`; текущие предпочтения моделей
не читаются. Проверяется source SHA, выбор профилей и полные SHA файлов ASR и
токенизатора до и после каждого модельного варианта. Каталог берётся из
`Resources/models.lock.json`; `--catalog` позволяет указать совместимый
закреплённый каталог. Он не генерируется и не перезаписывается.

Для `--tools` нужны standalone developer binaries из проверенной локальной
сборки. Копия FFmpeg внутри `.app` подписана с `app-sandbox`/`inherit` и требует
родительского App Sandbox; её прямой запуск из CLI может завершиться SIGABRT.
Стенд не меняет подпись или entitlements поставляемых инструментов.

Скрипт сам собирает opt-in XCTest и определяет путь к продуктам через
`swift build -c release --show-bin-path`. Для уже собранного SwiftPM-продукта
можно передать `--test-bundle /absolute/path/LocalScribeDiarizationTests.xctest`.
Обычный `swift test` пропускает probe без специальных переменных окружения.

Все четыре варианта работают offline по одному подготовленному PCM, с частями
по 300 с и без чтения ASR checkpoints. Каждому выделяется новый процесс и
каталог. Сеть запрещается и проверяется существующим `CWorkerIsolation` до
загрузки модели. SDK stdout/stderr непрерывно уходят в `/dev/null`; текст модели
не попадает в логи. Дочернему процессу передаётся ограниченный набор переменных
окружения. Прерывание завершает его группу процессов.

Исходник и модели читаются без изменения. Все копии аудио, экспериментальные
расшифровки и эталоны остаются в исключённом из Git `TestResults`. Новый каталог
не должен существовать; перезапись прежнего эксперимента запрещена.

`--prepare-only` создаёт WAV, фрагменты для прослушивания и шаблон эталона без
сборки/распознавания. `--timeout` задаёт предел в секундах для одного варианта.
После сбоя незавершённые части остаются для диагностики, но не используются
при следующем измерении. Числовой прогресс показывает объём запланированных
окон; это не точное завершённое покрытие речи.

## Артефакты и ручная проверка

- `input.json`, `environment.json` — закреплённые входы, SHA исходников стенда,
  бинарника XCTest и моделей, порядок вариантов. Они относятся к явному probe.
- `A`–`D` — отдельные `transcript.json`/`.txt`, `parts`, `measurement.json`,
  `decoding-options.json` и числовой `metrics-asr.json`. Расшифровки являются
  результатами эксперимента; числовые метрики по-прежнему не содержат речи.
- `comparison.md`/`.json` — сопоставление вызовов, времени и доступных оценок.
- `review.md`, `review-audio` — тексты четырёх вариантов и аудио выбранных мест
  созвона Индии: начало, Figma, эпики, распределение работы, координация, платёж,
  доступ. Эти интервалы — первичный контроль, не полный эталон встречи.
- `reference.template.json` — пустой неподтверждённый эталон; автоматический
  текст не подставляется как правильный ответ.
- `integrity.json` — проверка исходного SHA после прогона.

После прослушивания заполнить `text`, `verifiedBy` и только затем поставить
`verified: true`. Подтверждённый шум или тишину обозначать `kind: "nonSpeech"`,
`text: ""`; слова модели в таком интервале считаются ложными вставками.
Пустой текст без этой явной метки не принимается как эталон. WER отдельного
интервала без речи не определён; сохраняется число ложных слов. Неоднозначные слова нужно
разобрать до подтверждения. Подтверждённые интервалы не должны пересекаться.
Можно подготовить отдельный полный эталон с тем же source SHA и передать его
через `--reference`.

```sh
python3 scripts/probe_asr_matrix.py \
  --output 'TestResults/asr-matrix-fresh' --report-only \
  --reference 'TestResults/asr-matrix-fresh/reference.template.json'
```

Без подтверждённых интервалов WER отсутствует (`awaiting-reviewed-reference`),
победитель по качеству не выбирается. Для частичного эталона выводится только
WER выбранных интервалов (`partial-reviewed-reference`), а не всей встречи.
Отдельно вручную проверяются имена/термины, отрицания, числа, сроки, сохранность
реплик и дубли на стыках: WER не заменяет эту смысловую проверку.

Нормализация WER: Unicode NFKC, casefold, `ё→е`; пунктуация и дефисы разделяют
слова. Нет стемминга, перевода, раскрытия чисел и подмены терминов. Считаются
S/D/I обычным расстоянием Левенштейна; при равенстве предпочитаются S, D, I.
Слова гипотезы выбираются по середине исходного временного интервала; для
сегмента без word timings используется его середина. Заглушка `[неразборчиво]`
не удаляется из гипотезы. Границы эталонных интервалов лучше задавать на паузах.

Если пользователь подтвердил только оборванный границей кусок слова,
сохранить его дословно и указать `wordBoundaryTruncated: true`. Такой интервал
остаётся в отчёте с дословной оценкой, но исключается из суммарного WER.
Это предотвращает сравнение целого слова модели с обрезанным эталоном.
В Markdown показываются WER речи и число ложных слов на `nonSpeech` отдельно.
JSON `wer` включает вставки на `nonSpeech`, `speechWER` — только речевые
интервалы. При отсутствии эталонных слов WER равен `null`, а не нулю.
`nonSpeechBoundaryCrossingWords` отдельно отмечает слова, чьи середины попали
в `nonSpeech`, но границы выходят за него. Это может быть ошибкой выравнивания
соседней речи; счётчик сам по себе не доказывает галлюцинацию и не разрешает
удаление слова из расшифровки.

Для E `context-scores.json` сопоставляет исходную гипотезу и кандидата только
с подтверждёнными интервалами, точно совпадающими с границами цели повтора.
Эти оценки не относятся к целой встрече. Отчёты фиксируют SHA эталона и
скрипта оценки; текст автоматических гипотез не меняется при пересчёте.

Скорость сравнивается отдельно от загрузки модели. Условия охлаждения, питания
и кэша не фиксируются автоматически; thermal state до/после сохраняется, но не
заменяет контроль условий во время всего прогона. Температурные повторы могут
менять текст. Порядок A→B→C→D записан; близкие результаты следует повторять с
новыми каталогами и контролируемыми условиями. Исторические `asr6` live и
`asr7` offline результаты нельзя выдавать за эту контролируемую матрицу.

## Повтор сомнительного текста с изменённым контекстом: E

Вариант E использует поздние окна, как C, и дополнительно сохраняет альтернативы
для помеченного `uncertain` текста и энергетически заметных пропусков. Это
кандидаты для прослушивания: основной текст не заменяется, слова не вставляются,
автоматический выбор лучшей гипотезы отсутствует. Уверенно распознанную ошибку
эти признаки могут не обнаружить. Языковая стратегия, модель и фильтры прежние.

Перекрывающиеся цели и цели на расстоянии до 500 мс объединяются. Цель длиннее
20 с делится; для каждой выбирается до 30 с реального соседнего аудио с обеих
сторон по доступности. Вход не выходит за `originMs`/`durationMs`, что сохраняет
исходную шкалу времени и границы доступного live-контекста. Уже использованный
основной вход или вход восстановления пропускается. На основное окно допускается не более трёх повторов;
число отложенных целей и одинаковых входов явно сохраняется. Повторы не
запускают рекурсивные повторы. Отмена и ошибки прерывают технический прогон.

Включение требует явного `reviewContext` и отдельного приёмника артефактов.
Production оставляет его выключенным; версия pipeline и архив не меняются.
Для нового эксперимента добавьте к обычной команде:

```sh
--variants C E --output 'TestResults/asr-context-review-fresh'
```

По умолчанию стенд по-прежнему выполняет только A–D. В E JSON для каждого окна
сохраняется в `context-reviews`, отдельные аудиофрагменты — в
`context-review-audio`, пары исходного текста и кандидата — в
`context-review.md`. Обычный `transcript.json` содержит только основной
результат. Его WER не является оценкой неприменённых кандидатов. Отдельное
необязательное поле `contextReview` в числовых метриках считает стоимость
повторов без текста; старые метрики без этого поля продолжают читаться.

Проверено 20.10.2026: полный release-прогон — 305 XCTest, 0 ошибок,
4 опциональных пропуска; Python — 26 тестов, 0 ошибок. После усиления проверки
отмены отдельно выполнены 28 целевых XCTest, 0 ошибок, 1 opt-in пропуск.
Проверяются также отмена без исключения SDK, отсутствие замены исходных слов,
исходные таймкоды, ограничение доступного live-контекста, бюджет вызовов,
повторное использование одного декодирования и чтение старых метрик.

На 49-секундной технической копии реальной записи E завершился с локальными
весами и запретом сети: 3 основных окна, 1 повтор начала, 4 контекстных повтора,
4 пары гипотез, в одной нет текста кандидата. Время вызовов — 255,0 с.
Это проверка механизма; точность кандидатов не подтверждена прослушиванием,
WER отсутствует. SHA оригинала, подготовленного аудио и моделей проверены.
Обрезанный фрагмент имеет собственный SHA и шкалу времени с нуля, поэтому
этот результат нельзя сравнивать с C/D всей встречи как изолированный эффект.
Снимок исходников прогона сохранён; последние проверки отмены добавлены после
модельного прогона и проверены отдельным fake SDK тестом.

## Точечные предложения вместо замены всей реплики

`ASRWordRepair` формирует дополнительную гипотезу из уже полученных original и
candidate. Эталон алгоритму не передаётся. Production по-прежнему выключает
контекстные повторы; основной результат `SpeechRecognizer` не меняется.
Новые предложения сохраняются только внутри `wordRepair` технических
`context-reviews`. Поэтому версия пользовательского pipeline не повышается.

Два совпавших слова с близкими исходными таймкодами ограничивают участок
исправления. Выравнивание учитывает порядок, написание и середины слов с
допуском 500 мс. Для замены допускаются промежутки до трёх слов; каждое слово
кандидата должно однозначно соответствовать исходному по времени с
перекрытием не менее половины обоих интервалов. Исходный сегмент должен быть
неопределённым, кандидат — без флага неопределённости. Эти пороги являются
проверяемыми эвристиками, не оценкой вероятности правильного слова.

Пропущенные кандидатом исходные слова сохраняются. Добавления, различия на
краях без двух опор, неоднозначное выравнивание, межалфавитные замены,
защищённые отрицания и цифровые значения не применяются. При пустом кандидате,
отсутствии word timings или слишком большом входе возвращается исходный текст.
Размер LCS ограничен 256 словами на гипотезу; рекурсивных повторов нет.
Пунктуация и пробелы исходного слова сохраняются. Изменённый сегмент сохраняет
ID, участника, порядок и границы, остаётся неопределённым; старые word timings
для него удаляются. Неизменённые сегменты сохраняются целиком.

Пересечение словом границы цели, перекрывающийся повтор того же слова и
нарушение порядка таймкодов отмечаются отдельно. Пересечение само по себе
не разрешает удалить слово как шум. Новое принудительное выравнивание по
аудио и автоматическое исправление стыков этим алгоритмом не выполняются.

Чтобы проверить только склейку на фиксированных гипотезах E без новых вызовов
Whisper, используйте новый каталог:

```sh
python3 scripts/probe_asr_matrix.py \
  --repair-replay 'TestResults/completed-context-experiment' \
  --output 'TestResults/word-repair-fresh'
```

Стенд копирует E в новый каталог, проверяет SHA PCM и исходных гипотез,
запускает чистый XCTest с запретом сети и сохраняет предложения. Эталон
копируется только после выполнения Swift-алгоритма и используется Python
для оценки. `word-repair-info.json` явно указывает `newModelCalls: 0`;
`replay-environment.json` и `source-snapshot` закрепляют код и входы.
Время и метрики ASR в копии относятся к исходному модельному прогону.

`context-review.md` и `context-scores.json` сравнивают три гипотезы: исходный
текст, весь повтор и точечное предложение. Число оценённых интервалов
показывается для каждой гипотезы. Улучшение на тех же фрагментах, по которым
разрабатывался алгоритм, требует отдельной проверки на других данных.

Проверено 20.10.2026: на фиксированных E-гипотезах и 37 проверенных словах
точечное предложение даёт WER речи 27,0% против исходных 37,8% и 43,2% у
замены всей реплики. Пропуски: 1 / 1 / 13 соответственно. Предложены четыре
замены слов; новые вызовы Whisper отсутствуют. Ошибка на размеченном шуме
сохранена и помечена как пересечение границы. Это разработочная выборка,
поэтому автоматическая публикация предложений остаётся выключенной.

Полный release-прогон проверил 317 XCTest, 0 ошибок, 5 опциональных пропусков.
После последнего расширения тестов выравнивания целевой прогон проверил 37
XCTest, 0 ошибок, 2 opt-in пропуска. Python: 32 теста без ошибок; после
последней правки подсчёта предложений повторены 13 целевых тестов без ошибок.

## Проверка реализации 20.10.2026

Штатный `swift test -c release -j 4 --force-resolved-versions` завершился
без ошибок. После последнего изменения probe отдельно пересобран; opt-in
тест без явного входа корректно пропущен. Целевой прогон проверил 8
`ASRWindowTests` и 11 `SpeechRecognizerTests`, 0 ошибок. Шесть Python-тестов

цифровой тишины прошёл с локальными весами, проверенными SHA и запретом сети.
Это проверка стенда, а не качества речи.
