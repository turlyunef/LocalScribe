# Эксперимент: сверка с предрасшифровкой

Стенд `scripts/probe_live_caption_comparison.py` сравнивает сохранённый результат
основного ASR с новым результатом того же Apple Speech, который используется
во вкладке «В эфире». Он не изменяет приложение, архив, очередь, расшифровку,
диаризацию или итоги. Все кандидаты — предложения для изучения, не правки.
Версия пользовательского pipeline не меняется.

## Область проверки

Вход — до 20 законченных WAV-фрагментов длительностью до 180 секунд каждый,
mono PCM16 / 16 кГц, с началом шкалы в нуле и сохранённой основной расшифровкой.
Подача звука непрерывная; при потере хотя бы одного буфера опыт отклоняется.
Незавершённые гипотезы не включаются в сравнение и считаются отдельно.
Языки: `russian`, `english`, `mixed`. Пакеты Apple Speech должны быть уже
установлены через приложение: стенд не инициирует их загрузку.

Это повтор готового звука, а не проверка настоящей записи с микрофона.
Не проверяются переключение языков, восстановление Speech после ошибки,
переполнение потока под нагрузкой и длительные встречи. Старый
`live-captions.json` не используется: он не содержит временной привязки.
Сохранение доказательной предрасшифровки для новых записей остаётся отдельным
этапом после оценки пользы алгоритма.

## Запуск

Файл входа имеет следующий формат; SHA-256 относятся к фактическим байтам файлов:

```json
{
  "schemaVersion": 1,
  "sources": [{
    "id": "clip01",
    "audioPath": "/absolute/path/clip.wav",
    "audioSHA256": "<SHA-256 WAV>",
    "transcriptPath": "/absolute/path/transcript.json",
    "transcriptSHA256": "<SHA-256 transcript.json>",
    "durationMs": 30000,
    "language": "mixed"
  }]
}
```

`transcript.json` — контракт Transcript версии 1 с исходными `segments`
и необязательными `words`; его шкала должна совпадать с WAV. Результат от
другого аудио недопустим: проверка хэшей закрепляет файлы, но происхождение
пары нужно установить при подготовке опыта.

```sh
xcrun --find metal
swift test -c release -j 4 --force-resolved-versions --filter LiveCaptionComparisonProbeTests
python3 scripts/probe_live_caption_comparison.py \
  --input TestResults/caption-input.json \
  --output TestResults/caption-comparison-new \
  --speed 1
```

Стенд сам найдёт путь XCTest через SwiftPM. Уже собранный bundle можно передать
через `--test-bundle /absolute/path/LocalScribeUITests.xctest`. Для Speech и
системного ModuleCache может потребоваться запуск с разрешённым системным
доступом. Sandbox/entitlements приложения не меняются.

`--output` должен быть новым подкаталогом `TestResults`. Фиксируются хэши
входов, бинарника, исходников и снимок кода, версия macOS и архитектура.
Каталог создаётся с правами 0700; исходные аудио и результаты не переписываются.
Нативный вывод SDK не выводится в консоль. Успешная обработка всех источников
закрепляется `completed.json`; частичный/изменённый опыт не оценивается.

`--speed 1` подаёт звук в обычном темпе, `--speed 4` — ускоренно. Время повтора
включает ожидание подачи и подготовку Speech: это **не** добавочная задержка
финального ASR и не измерение нагрузки во время реальной записи.

## Выбор кандидатов и оценка

Нормализация: NFKC, регистр, ё/е, разбиение по пунктуации; без перевода,
стемминга и преобразования чисел. Совпавшие участки текста служат опорами.
Для кандидата нужны по два совпавших слова с обеих сторон, совместимые
временные интервалы опор с допуском 1000 мс и различие до пяти слов.
Удаления слов только на основании их отсутствия у Apple отклоняются.
Числа, латиница и отрицания дополнительно отмечаются как чувствительные.
Проверяются также пропуски и расхождения без `uncertain`.

Временные границы Apple здесь относятся к фразам; уверенность и точные времена
отдельных слов не доступны через текущий callback. Сопоставление поэтому
остаётся грубым, в том числе для повторяющихся фраз. Условия отбора не являются
достаточным основанием для автоматического применения.

Необязательный `--reference TestResults/caption-reference.json` включает WER:

```json
{
  "schemaVersion": 1,
  "sources": [{
    "id": "clip01",
    "audioSHA256": "<SHA-256 того же WAV>",
    "verified": true,
    "provenance": "Кем и откуда получен проверенный эталон",
    "text": "Точный текст всего фрагмента"
  }]
}
```

Эталон читается только после распознавания и выбора кандидатов и не передаётся
Speech. `verified: true` ставится после проверки происхождения эталона и
соответствия аудио; текст другой ASR-модели эталоном не является. Для текста
датасета явно указывать, была ли дополнительная ручная проверка аудио.
На разметке только отдельных участков этот режим полной WER использовать нельзя.

`comparison.json` и `comparison.md` сохраняют все расхождения, причины отказа,
время повтора и число исключённых гипотез. При наличии эталона считаются WER
основного ASR, Apple, гипотетического применения **всех** отобранных кандидатов
и изменение числа ошибок для каждого кандидата отдельно. Эталон не выбирает
победившие замены. Улучшение WER из-за записи числа словами нужно отличать от
восстановления действительно потерянного содержания. Без слов в эталоне WER
не определена, но вставки считаются.

Повторная оценка готового опыта без новых вызовов Speech:

```sh
python3 scripts/probe_live_caption_comparison.py \
  --output TestResults/caption-comparison-new \
  --reference TestResults/caption-reference.json \
  --score-only
```

Отчёт сохраняет хэш кода оценивания и эталона. Изменять пороги по открытому
эталону и выдавать результат за независимую приёмку нельзя.

## Первое наблюдение — 17.11.2026

Четыре ранее использованных фрагмента Podlodka: 108,778 секунды, 252 слова
по текстам датасета, revision `4a9161485a70ea849ccaa54a72faa9bfc0a60627`.
Дополнительной ручной вычитки аудио не было. Основная расшифровка — сохранённый
Whisper из `asr-neural-boundaries-20261115/production`, Apple — свежий mixed replay.
Это открытый разработочный материал, не новый независимый набор.

При ускоренной подаче ×4 получены 34 расхождения, из них 14 кандидатов для
проверки. Три кандидата восстанавливают пропущенные слова. Ещё одно уменьшение
WER связано с написанием числа словами. Девять кандидатов увеличивают число
ошибок, один оставляет его прежним. WER основной расшифровки — 21/252 (8,33%),
Apple — 51/252 (20,24%), гипотетического применения всех кандидатов —
30/252 (11,90%). На всех четырёх источниках `uncertain` отсутствует: только
этот признак не позволил бы найти восстановленные слова.

Прогон ×4 завершён без потерь буферов и незавершённых фраз; сумма времени
повторов — около 29,45 секунды, включая подачу 108,778 секунды звука ×4.
Артефакты — `TestResults/caption-comparison-20261117-v1-system`.

Повтор того же опыта с подачей ×1, без изменения правил отбора: 33 расхождения,
13 кандидатов. Три пропуска восстановлены, ещё одно уменьшение WER связано
с числом; восемь кандидатов увеличивают ошибки, один сохраняет их число.
WER Apple — 50/252 (19,84%), гипотетического применения всех кандидатов —
29/252 (11,51%) при прежних 8,33% основного ASR. Потерь буферов и незавершённых
фраз нет. Сумма времени повторов — 110,81 секунды, включая подачу звука.
Артефакты — `TestResults/caption-comparison-20261117-v1-realtime`.

Сверка уже готовых текстов в памяти на всех четырёх фрагментах: медиана 0,85 мс,
максимум 1,20 мс в 20 повторах. Исключены ASR, чтение файлов и оценка по эталону;
результат не описывает длительные встречи или нагрузку Apple Speech.
Замер — `comparison-cost.json` в каталоге опыта ×4.

Проверки: 12 профильных XCTest (0 ошибок, 2 ожидаемых opt-in пропуска),
оба явных нативных опыта ×4/×1 завершены успешно. Статическая проверка
`bash scripts/verify.sh --static` прошла, включая 78 Python-тестов. Полный
Swift-прогон и новая микрофонная приёмка в рамках этого стенда не выполнялись.

Первый результат подтверждает возможность восстановить отдельные пропуски,
но не подтверждает безопасность автоматических замен. Нужны независимые
реальные встречи, собственные временные метки исходного PCM и отдельная
проверка достоверности исправлений; Qwen/GigaAM этим опытом не оценивались.
