# Исправление лишнего участника в конце записи

18.10.2026. Внедрено отражающее дополнение неполного входа SpeakerKit,
проверенное в локальном исследовании записи длиной 37,9 секунды.
На этом примере исходный SDK давал A–B–C, исправленный — A–B–A.
Первый и третий голоса принадлежат одному человеку по подтверждению пользователя.
Аудио и текст беседы в репозиторий не добавлены.

## Реализация

`ThirdParty/SpeakerKit` содержит отслеживаемую копию 18 файлов SpeakerKit
из Argmax OSS 1.1.1, revision `1bbc57cb7fe6410248a685b1c5a3c6d56adc2ed4`.
Она компилируется как `LocalScribeSpeakerKit` с режимом Swift 6 и concurrency
настройками закреплённого `Package@swift-6.2.swift`. Worker и его технический
probe используют этот модуль. WhisperKit, ArgmaxCore и модельные веса прежние;
удалённые зависимости и `Package.resolved` не изменены.

В `SpeakerSegmenterModel.predict` только неполный блок дополняется до 30 секунд
попеременно обратной и прямой копиями настоящих сэмплов. Это тот же алгоритм,
что в исследовательском патче, вынесенный в тестируемую функцию `reflectTail`.
Полный и пустой блоки не меняются. `waveformLength` по-прежнему вычисляется
из реального числа сэмплов до дополнения. Stride, ограничение окон embedder,
начало записи и глобальная кластеризация не изменены.

`VoiceInterval.clipped` ограничивает публикуемые интервалы длительностью
исходника и отбрасывает интервалы вне записи, пустые и нечисловые границы.
Перекрытия голосов сохраняются. Отражённый звук существует только в памяти
как контекст входа модели, не записывается в оригинал или рабочий WAV.

`RunInfo.pipelineVersion` теперь `1.0.0-audio2-asr5-live1-diarization2-summary11`:
новые задания получают другой fingerprint. Старые задания декодируются со
своей версией и прежним fingerprint, в том числе без `modelIDs`.
Обычная очередь создаёт новое задание при несовпадении версии;
прошлый active run сохраняется до успешной публикации нового.
Пересоздание только итогов из исправленной вручную транскрипции по-прежнему
использует её без повторной диаризации. Автоматической миграции готовых
пользовательских результатов нет; для нового разделения участников нужно
явно повторить полный анализ записи.

Исходная ревизия, SHA-256 каждого upstream-файла, лицензия, уведомления и
точный diff сохранены рядом со снимком. Проверка обратного применения патча
подтвердила совпадение всех 18 файлов с исходными SHA-256. Лицензии копируются
в `.app` из репозитория; исправление не зависит от правки `.build/checkouts`.
Причина выбора алгоритма: [upstream issue #485](https://github.com/argmaxinc/argmax-oss-swift/issues/485).

## Выполненные проверки

- `swift build -c release -j 4 --force-resolved-versions` — успешно.
- `bash scripts/build_app.sh` — успешно; `dist/LocalScribe.app` собрана,
  штатная ad-hoc подпись прошла `codesign --verify --deep --strict`.
  Лицензии снимка включены в bundle. Сборка использовала имеющиеся
  Metal-артефакты; чистая сборка MLX на пустом кэше здесь не проверялась.
- Все XCTest с локальными регрессионными данными: 120 тестов, 0 ошибок,
  0 пропусков: 71 Core/model/live-capture, 41 UI/coordinator, 8 новых проверок
  диаризации. Журнал — `TestResults/diarization-tail-fix-tests.log`.
- Проверены отражение, отсутствие изменения реального префикса, пустой вход,
  цифровая тишина, один сэмпл, полные блоки и длины около 30 секунд.
- Настоящий Core ML segmenter проверен на длинах 1 и 1600 сэмплов,
  480000 ± 1 сэмпл и 480000 + реальный stride ± 1 сэмпл. Проверяются число
  блоков, реальные `waveformLength`, содержимое дополнения и успешный inference.
- Проверены границы окон embedder, отсечение интервалов после конца записи,
  сохранение overlap, совместимость старого fingerprint и новый fingerprint.
- Все 25 файлов локальной модели совпали по размерам и SHA-256 с каталогом.
- Собранный worker с включённой штатной сетевой изоляцией выполнил диаризацию
  изолированной копии примера: два участника, пять интервалов, A–B–A;
  последний опубликованный интервал заканчивается на 37232 ms при длине
  37900 ms. Проверены fingerprint и неизменность исходника, ASR, manifest
  и прежнего active run. Вместо текста разговора в ASR использованы нейтральные
  технические слова в трёх контрольных интервалах. Результат проверки —
  `TestResults/diarization-tail-fix/worker-regression.json`.

Модельные проверки включаются переменными окружения:

```sh
LOCALSCRIBE_DIARIZATION_FIXTURE_WAV=/absolute/path/to/regression.wav \
LOCALSCRIBE_DIARIZATION_FIXTURE_MODELS=/absolute/path/to/diarization \
swift test -c release -j 4 --force-resolved-versions
```

WAV — именно локальный пример исследования: mono 16 kHz, 606400 сэмплов.
Папка моделей содержит `speaker_segmenter`, `speaker_embedder` и
`speaker_clusterer`. Без переменных два модельных теста явно пропускаются;
остальные шесть выполняются без весов и частной записи.

## Что остаётся проверить

Это исправление подтверждено для конкретного регрессионного примера и
технических границ входа. DER не считался. Нужны размеченные записи с одним,
двумя и несколькими голосами, очень короткой речью, overlap, возвратом
участника через длительную паузу и настоящие длинные встречи.
Отражённый контекст может влиять на сегментацию короткой речи; корректность
на всех таких записях выполненными тестами не установлена.
