## 4. Карта реализации и её ограничения

- `Sources/LocalScribeCore/Analysis.swift`: первая/поздняя пауза,
  энергетические проверки отсутствующего начала и внутренних промежутков.
- `Sources/LocalScribeWorker/SpeechRecognizer.swift`:
  `ASRRecognitionPolicy`, общий декодер, повтор начала, экспериментальные
  gap/context-повторы. Production — `.production`, первая пауза.
- `Sources/LocalScribeWorker/ASRContextReview.swift`: выбор целей и сохранение
  пары гипотез; цель до 20 с, контекст до 30 с, до трёх повторов на окно.
  Использованный контекст пропускается; одинаковые входы соседних целей
  используют один результат. Сеть и модельные параметры не меняются.
- `Sources/LocalScribeWorker/ASRWordRepair.swift`: `asr-word-repair-v1`.
  LCS до 256 слов на гипотезу, опорные слова с допуском 500 мс, различия до
  трёх слов, для подстановки минимум 50% перекрытия обоих временных интервалов.
  Меняются только неопределённые исходные слова по однозначному, не помеченному
  неопределённым кандидату. Пропуски/вставки и края без двух опор сохраняют
  оригинал; защищены отдельные отрицания и цифровые значения. Числа, написанные
  словами, не покрыты общей гарантией. Уверенность SDK не доказывает правильность.
- В изменённом предложении сохраняются ID, участник, порядок, границы,
  неопределённость; старые word timings сегмента удаляются. Неизменённые
  сегменты сохраняются целиком. Межалфавитные замены не выполняются.
- Полностью отсутствующую речь `ASRWordRepair` восстановить не может:
  для точечной замены нужны исходные слова и временные опоры.
- Стыки сейчас диагностируются, а не исправляются новым выравниванием по аудио.
- `Sources/LocalScribeWorker/ASRMetrics.swift`: числовые метрики, опциональное
  `contextReview`; старые метрики остаются читаемыми, текста в них нет.
- `Tests/LocalScribeDiarizationTests/ASRMatrixProbeTests.swift`: opt-in
  модельный прогон и replay без модели. Остальные ASR-тесты рядом;
  планировщик дополнительно проверяется в [ASRWindowTests.swift](../Tests/LocalScribeDiarizationTests/ASRWindowTests.swift).
- `Tests/LocalScribeDiarizationTests/ASRFrozenBaselineProbeTests.swift`:

Не скрывать важную работу будущего внедрения: предложение возвращает индексы
сегментов/слов **в обрезанном подмножестве**, а production должен менять
исходный core-сегмент. Все временные ASR ID могут быть `tmp`; ID не дают
уникального соответствия. Наивная склейка `proposed` разных целей создаст
дубли/потери. До внедрения нужна стабильная внутренняя адресация исходных
сегментов и слов и однократное применение набора правок.

## 5. Инструменты, оценка и обязательные ограничения

1. Сохранять один последовательный worker, локальность, запрет сети,
   полные SHA, атомарные JSON, actors/Sendable и правила `AGENTS.md`.
   Не править `.build/checkouts`, entitlements, подпись и схему архива ради теста.
2. Архив и старые результаты читать без изменения. Все экспериментальные
   результаты — в новых каталогах `TestResults`; прежние прогоны не затирать.
3. Не выводить полное окружение и не запускать `xctest -help`.
   Ранее ошибочный вызов напечатал окружение с credential. Сам секрет
   не читать, не воспроизводить и не проверять. Использовать
   `process_environment()` из скрипта: он передаёт только безопасный allowlist.
   SDK stdout/stderr отбрасывать; речь сохранять только в явных артефактах probe.
4. Для сборки и Core ML могут потребоваться разрешённые системные кэши вне
   файловой песочницы. Не обходить это ослаблением сетевой изоляции приложения.
5. Декодер закреплён: language=nil, detectLanguage=true, fallbackCount=2,
   wordTimestamps=true, windowClipTime=0, concurrentWorkerCount=1.
   Варианты менять по одному фактору, фиксируя опции и SHA кода/моделей.
6. Эталон даёт пользователь после прослушивания. Автоматический текст не
   становится эталоном из-за связности. `verified=true` требует `verifiedBy`.
   Шум: `kind=nonSpeech`, `text=""`; WER без эталонных слов — null.
   `wordBoundaryTruncated=true` исключает обрезанное слово из суммарного WER.
7. `speechWER` считает только речь; `wer` включает вставки на nonSpeech.
   Отдельно считать S/D/I, слова на шуме и пересечения границ. Для предложений
   в точно совпавшей цели использовать сохранённую принадлежность слов цели:
   снятые word timings не должны случайно исключать текст из оценки.
8. Дополнительно проверять отрицания, числа/сроки, имена, термины, отношения
   между фактами, пропущенные реплики и дубли. WER не заменяет смысловую проверку.
9. Никакой процент на выбранных фрагментах не выдавать за WER всей встречи.
   После настройки по контрольному фрагменту он становится разработочным;
   для итоговой проверки нужны новые данные. Желательна другая реальная встреча.

Команды выполнять из корня. Swift запускать с очищенным окружением, например:


Не повторять полные A–D без новой причины. Replay можно воспроизвести так:


путь XCTest через SwiftPM; жёсткий `.build/out/...` не использовать.
