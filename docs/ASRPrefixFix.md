# Пропуск начала расшифровки

18.10.2026 локально воспроизведён пропуск на микрофонной записи длительностью 26,8 секунды с профилем Whisper Turbo. Первая реплика сохранённого ASR начиналась с 13,38 секунды; диаризация и UI получали уже неполный текст. Исходное аудио содержало звук в пропущенном интервале.

Разбиение по паузе создавало основное окно 0–13,84 секунды и вход модели 0–14,84 секунды с правым контекстом. Whisper возвращал для него сегмент без текста и слов, при этом `noSpeechProb = 0` и `avgLogprob = 0`: фильтр уверенности не объяснял пропуск. Та же модель на входе 0–26,8 секунды возвращала слова начиная с 0,94 секунды. Это зависимость результата декодера от контекста; изменение отображаемого таймкода не восстановило бы слова.

`SpeechRecognizer` теперь проверяет отсутствующее начало каждого окна. Если пропуск составляет минимум 1,5 секунды и содержит минимум 600 мс заметного сигнала, выполняется один повтор с реальным контекстом до 30 секунд. Последние 500 мс перед первым словом исключаются из проверки энергии, чтобы небольшая погрешность выравнивания не считалась потерей. Из повтора принимаются только слова отсутствующего начала по их серединам; основной результат сохраняется. Если повтор не помог, worker отправляет предупреждение. Длительная тишина и короткий шум сами по себе повтор не вызывают; постоянный шум может его вызвать, поскольку энергия не является детектором речи.

Основное окно ограничено 28 секундами, чтобы вместе с контекстом не превышать 30 секунд. `windowClipTime = 0` позволяет SDK обрабатывать и остатки короче секунды. Версия pipeline повышена до `asr5`; старые готовые результаты автоматически не переписываются.

Проверка исправленного production-кода на том же исходнике вернула шесть сегментов: 0,94–3,24; 3,66–5,04; 6,84–11,18; 12,30–13,38; 13,38–21,02; 21,10–26,22 секунды. Контрактная проверка таймкодов пройдена. Пользовательский архив читался без изменения; аудио и текст не добавлялись в репозиторий, SDK stderr отбрасывался, диагностика выводила только числовые оценки, таймкоды и языки. Все прогоны модели выполнялись с запретом сети.

Регрессионные XCTest проверяют пустое и позднее начало, сохранение исходной шкалы времени, исключение левого контекста, тишины и короткого шума. Это ограниченное исправление воспроизведённого дефекта, а не гарантия полноты распознавания любой речи: WER, смешение языков и слова на стыках требуют проверки по эталону.

`swift test -c release -j 4 --force-resolved-versions` завершился успешно: Core и UI XCTest без ошибок. На техническом RU → EN → RU аудио исправленный SpeechRecognizer сохранил оба языка и валидные исходные таймкоды. `python3 scripts/probe_live_capture.py` подтвердил первую контрольную точку до завершения записи, отмену по EOF, её неизменность после возобновления и последний интервал до 40 125 мс. Использованы существующие Metal-артефакты сборки; чистая сборка Metal отдельно не подтверждалась. SHA-256 пользовательского оригинала после диагностики совпал с manifest; временный диагностический WAV удалён. Установленная `.app` в рамках этой проверки не обновлялась.
