# LocalScribe

Нативное локальное приложение для Apple Silicon, macOS 26+. Запись встроенного микрофона, импорт AAC (ADTS)/MP3/M4A/WAV/FLAC/OGG/OPUS, Whisper на выбор, SpeakerKit OSS, Qwen3.5 через MLX. Результаты только для чтения, копирование, MD/TXT. Редактора, системного захвата звука, серверов и облачного анализа нет.

**Текущая версия — 2.10.1.** Версия задаётся явно; автоматического пересчёта при сборке нет.

**В версии 0.1.1** исправлена немедленная остановка записи; [проверка микрофона](docs/MicrophoneFix.md).

**Это предварительная реализация.** Состояние фактических проверок и ограничения см. [docs/Acceptance.md](docs/Acceptance.md), журнал выбора компонентов — [docs/Stage0.md](docs/Stage0.md). Наличие исходного кода не означает, что пройдена трёхчасовая приёмка.

## Сборка на Mac

Проверяемая среда разработки: M1/16 GB, Xcode 27.0, Swift 6.4, Metal Toolchain 27A266a. Deployment target — macOS 26. Для воспроизведения используйте эту версию Xcode; сборка другими версиями Xcode отдельно не подтверждена. На более мощном Mac с Apple Silicon используются те же команды сборки. Python 3 нужен только разработчику для упаковки лицензий и тестов. Пользователю готового .app Python не нужен.

### Подготовка нового Mac

Нужен Mac с Apple Silicon и версией macOS, на которой работает Xcode 27.0. Минимальная macOS 26 у приложения не означает, что эта версия ОС подходит для запуска самого Xcode. Установите полный Xcode: одного пакета Command Line Tools недостаточно. Если Xcode находится в `/Applications/Xcode.app`, выполните в Terminal:

```sh
sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer
sudo xcodebuild -runFirstLaunch
xcodebuild -downloadComponent MetalToolchain
```

Если Xcode установлен в другую папку, укажите её в первой команде. `-runFirstLaunch` принимает лицензию и устанавливает компоненты первого запуска. Metal Toolchain также можно установить через Xcode → Settings → Components; [официальная инструкция Apple](https://developer.apple.com/documentation/xcode/downloading-and-installing-additional-xcode-components).

Проверьте выбранную среду:

```sh
uname -m
xcodebuild -version
swift --version
python3 --version
```

Ожидаются `arm64`, Xcode 27.0, Swift 6.4 и доступный Python 3. Если `python3` отсутствует, установите Python 3 до упаковки приложения. Для первоначальной загрузки SwiftPM-зависимостей и исходников FFmpeg нужен интернет; веса моделей на этапе сборки не требуются.

### Перенос исходников

Для переноса через Git зафиксируйте все нужные изменения. Если клонируете удалённый репозиторий, нужный коммит сначала должен быть отправлен в него: локальный `git commit` сам по себе не обновляет удалённую копию. При переносе папки репозитория для дальнейшей разработки сохраните и скрытую папку `.git`.

Можно перенести текущее рабочее дерево отдельным исходным архивом. На старом Mac из корня проекта выполните:

```sh
bash scripts/package_source.sh
```

Скопируйте `dist/LocalScribe-source.tar.gz` на новый Mac. Архив включает изменённые и ещё не добавленные в Git исходники, в том числе локальные реализации из `ThirdParty/`. История Git, сборочные кэши, `Assets/`, `build/`, `dist/` и `TestResults/` в него не входят. Для примера ниже положите архив в Downloads; целевая папка `meetings_AI` ещё не должна существовать:

```sh
mkdir -p "$HOME/VibeProjects"
mkdir "$HOME/VibeProjects/meetings_AI"
tar -xzf "$HOME/Downloads/LocalScribe-source.tar.gz" -C "$HOME/VibeProjects/meetings_AI"
cd "$HOME/VibeProjects/meetings_AI"
```

Расположение проекта и имя пользователя могут быть другими. Переносите проект целиком, включая `Package.swift`, `Package.resolved`, `Resources/models.lock.json` и локальные исходники `ThirdParty/`; генераторы каталогов моделей для обычной сборки запускать не нужно.

### Сборка и проверка запуска

Из корня перенесённого проекта выполните обе команды сборки, затем откройте приложение:

```sh
bash scripts/build_ffmpeg.sh
bash scripts/build_app.sh
open dist/LocalScribe.app
```

Вторая команда создаёт `dist/LocalScribe.app`, включает worker, XPC-загрузчик, статические FFmpeg/ffprobe и SwiftPM/Metal-ресурсы. Зависимости из `Package.resolved`, без плавающего main. Каталог моделей в `Resources/models.lock.json`; перегенерировать его для обычной сборки нельзя. Каждая сборка FFmpeg проверяет закреплённую SHA-256 копии архива и извлекает её в новый временный каталог, который удаляется при завершении. Существующее дерево `Vendor/ffmpeg-8.0.1` не используется и не изменяется. Конфигурация, хэши и лицензии проверенных исходников сохраняются в `build/`. Если инструменты собраны прежним скриптом, один раз повторите `bash scripts/build_ffmpeg.sh` перед упаковкой, чтобы подготовить лицензии в новом расположении.

На новом Mac не переносите одни готовые `Assets/tools` вместо первой команды: упаковке также нужны создаваемые ею `build/ffmpeg-licenses` и `build/ffmpeg-sha256.txt`. Один `swift build` не создаёт готовую `.app`.

По умолчанию используется ad-hoc подпись для личной локальной сборки. Для Developer ID задайте `LOCALSCRIBE_SIGN_IDENTITY`; notarization для распространения выполняется отдельно. Отключать Gatekeeper или системную защиту не требуется. Полнота App Sandbox/TCC-проверки указана в отчёте.

Для ad-hoc сборки сертификат разработчика не нужен. Если переменная `LOCALSCRIBE_SIGN_IDENTITY` уже задана, соответствующая identity должна быть доступна на новом Mac; для возврата к подписи по умолчанию выполните `unset LOCALSCRIBE_SIGN_IDENTITY` перед сборкой.

После запуска выполните шаги из раздела [«Первый запуск»](#первый-запуск): загрузите модели или импортируйте их отдельными папками и разрешите микрофон на новом устройстве. Проверьте короткую запись с расшифровкой и итогами, а также импорт аудиофайла. Модели и пользовательский архив хранятся отдельно от исходников; сборка и распаковка исходного архива их не переносят.

Проверка переноса 29.10.2026: изучены сборочные скрипты и состав исходного архива; отдельная чистая проба SwiftPM со Swift 6.4 успешно создала Metal-библиотеку без прежних артефактов. Полная чистая сборка LocalScribe.app и запуск на другом физическом Mac в эту проверку не входили.

Исходник иконки — [Resources/AppIcon.png](Resources/AppIcon.png) с прозрачным полем вокруг значка. `bash scripts/build_icon.sh` создаёт [Resources/AppIcon.icns](Resources/AppIcon.icns) со всеми размерами macOS от 16 до 1024 px через системные `sips` и `iconutil`. Упаковщик запускает эту команду автоматически и включает иконку в `.app`.

После упаковки обновляется дата самого `.app`, чтобы macOS обнаружила изменения иконки при замене прежней сборки. Если установленное приложение продолжает показывать стандартный значок, выполните `bash scripts/refresh_app_icon.sh /Applications/LocalScribe.app`: команда проверяет подпись и обновляет регистрацию только LocalScribe в Launch Services.

## Первый запуск

1. Откройте локально собранный `dist/LocalScribe.app`. Можно переместить его в Applications.
2. В настройках выберите модель распознавания и модель итогов, затем нажмите «Загрузить выбранные». Доступны Whisper base / small / medium / large-v3-turbo / large-v3 и итоговые Qwen3.5 2B / 4B / 9B / 27B / 122B-A10B в разных квантованиях (4–8 бит), а также экспериментальные профили Qwen3-ASR и VibeVoice-ASR (только готовые записи). Объём скачивания показывается до запуска; для исходного комплекта large-v3 + 9B это около 9,1 GB. Приложение автоматически добавит нужный токенизатор и SpeakerKit, покажет общий процент и объём всех файлов текущей модели, счётчик проверенных файлов и раскрываемый список. Размеры и SHA-256 проверяются до готовности. Повтор загрузки сохраняет проверенные файлы; незавершённый большой файл скачивается снова.
3. Можно вместо сети выбрать «Импортировать из папки…» для каждого профиля. Папка должна содержать точный комплект из `models.lock.json`, без дополнительного верхнего каталога. Для ASR это содержимое соответствующего `openai_whisper-…/`; SpeakerKit сохраняет вложенную структуру `speaker_*`; tokenizer — отдельная папка. Для small / medium нужен `tokenizer-multilingual`, для large-v3 / turbo — `tokenizer`. При импорте из папки токенизатор также импортируется отдельно. Произвольные Python-модели не запускаются.
4. Нажмите «Новая запись», прочитайте подсказку и «Начать». При первом запуске разрешите микрофон в системном диалоге. Запись разрешена и до установки моделей. Внешний микрофон или AirPods автоматически не выбираются.
5. После остановки запись сохраняется и поступает в очередь. Для импорта выберите файл или перетащите его в окно. Внешний оригинал не изменяется. Файлы длиннее трёх часов отклоняются целиком.
6. Во вкладках «Расшифровка»/«Итоги» можно выделять текст. Предупреждения собраны в отдельной вкладке «Предупреждения», которая появляется только при их наличии. «Копировать» копирует текущую вкладку; меню позволяет выбрать раздел или всё вместе. Экспорт MD/TXT не обращается к моделям; вариант «Всё» включает предупреждения. Ссылки из итогов переходят к репликам. Аудио открывается через «Показать аудио в Finder».

Голоса удалённых участников в наушниках микрофон не слышит. Используйте готовую запись для импорта. Перед записью убедитесь, что участники о ней знают.

В списке «Загруженные модели» галочка выбирает одну модель распознавания и одну модель итогов. Последняя успешно загруженная или импортированная модель становится выбранной для своего этапа; остальные остаются на диске. Выбор сохраняется между запусками. Красная корзинка удаляет только соответствующую модель после подтверждения; при удалении выбранной используется последняя установленная из оставшихся совместимых моделей. Если обязательного компонента больше нет, новая обработка недоступна до его установки, но архив и экспорт продолжают работать.

Установка, переключение и удаление моделей не запускают повторную обработку записей, в том числе ожидающих модели. Для существующей записи нажмите «Продолжить», «Обработать заново» или «Пересоздать итоги». Пересоздание итогов использует имеющуюся расшифровку и сохраняет предыдущий успешный результат до завершения.

Раздел «Этот Mac» показывает чип, число ядер CPU, RAM и бюджет памяти GPU из Metal. Перед загрузкой, импортом или выбором тяжёлой модели появляется предупреждение, если физической памяти или бюджета Metal меньше ориентировочных требований. Например, для Qwen3.5 27B предусмотрен ориентир 32 ГБ RAM и 24 ГБ рабочего объёма GPU. Это консервативная оценка, а не результат замеров или гарантия запуска: влияют контекст и другие приложения. Модели обрабатывают этапы по очереди, поэтому объём всех скачанных весов не складывается в требование к RAM. Наличие новых вариантов в каталоге не означает, что для каждого измерены качество и скорость на данном Mac.

На машине разработки уже загружены и проверены `Assets/models/asr`, `Assets/models/diarization`, `Assets/models/summary`, `Assets/models/tokenizer`: их можно выбрать соответствующими кнопками «Из папки…», чтобы не скачивать веса повторно. Эти 9,1 GB не входят в .app или исходный архив. После импорта моделей проверьте сценарий при физически отключённой сети.

## Схемы

В заголовке левой колонки рядом с кнопками групп находится переключатель «Записи»/«Схемы». У каждого раздела своё выделение, поиск и группы. Переключение не прерывает импорт, запись микрофона или обработку.

1. В режиме «Схемы» нажмите «Загрузить изображение» (или кнопку с фото-иконкой в заголовке списка) и выберите один или несколько PNG/JPEG. Файлы также можно перетащить из Finder в правую область для импорта в группу по умолчанию или прямо на нужную группу. Приложение импортирует их по порядку. Для дубля можно открыть существующую схему, импортировать ещё раз или пропустить файл. На каждый полностью декодируемый файл действуют ограничения до 30 МиБ, 24 мегапикселей и 8192 px по стороне. В архив сохраняется побайтовая копия оригинала.
2. Во вкладке «Схемы» в настройках выберите и загрузите Qwen3-VL 4B, 8B или 32B. Приложение рекомендует модель с учётом RAM и бюджета Metal. Пока совместимая модель схем не выбрана, схема остаётся в статусе «Ожидает модель». После установки нажмите «Распознать».
3. Схема автоматически встаёт в общую очередь с записями (одна локальная обработка за раз). Действие «Поднять на верх очереди» ставит схему следующей после текущего задания. Статусы включают «Ожидает модель», «В очереди», «Распознаётся», «Распознана», «Распознана с предупреждениями», «Ошибка», «Прервана», «Отменена». Ошибки модели не портят предыдущий успешный результат; повтор всегда создаёт новую попытку.
4. Рядом с оригиналом доступны вкладки «Узлы», «Связи» и, при наличии, «Предупреждения». Нечитаемые подписи и неподтверждённые связи помечаются. Изображение без схемы отклоняется с объяснением. «Копировать» копирует открытую вкладку, а из меню можно выбрать любой раздел или «Всё». «Сохранить» экспортирует раздел или весь результат в Markdown (.md) и текст (.txt), а также целую схему в PlantUML (.puml). В карточке можно открыть архивный оригинал в Finder, изменить название кликом по заголовку или удалить открытую схему после подтверждения. Для UML-диаграмм последовательности PlantUML сохраняет порядок сообщений и пунктир ответов. Чтобы получить типы связей для старой схемы, нажмите «Распознать заново».
5. Группы схем управляются отдельно от групп записей. При удалении можно перенести схемы в «Без темы» или удалить группу вместе с архивными копиями изображений и результатами. Внешние оригиналы и экспорты сохраняются.

Распознавание выполняется локально через MLX на Apple Silicon. Целевой ввод — читаемые изображения блок-схем, архитектурных схем и UML. Подробности о поддерживаемых связях и замеры есть в [документации распознавания схем](docs/DiagramRecognition.md).

## Данные и восстановление

Корень определяется через FileManager Application Support внутри sandbox-контейнера. В настройках есть «Показать папку данных». Исходники, метаданные и результаты лежат в `recordings/<uuid>/`, модели — в `models/`. Приложение не сохраняет SDK stderr: он непрерывно считывается и отбрасывается. Телеметрии нет. GUI и worker не имеют сетевых прав; worker проверяет запрет до загрузки модели. Только отдельный XPC-загрузчик имеет сеть: ему передаются ID профиля и индекс файла из закреплённого каталога, а не аудио, текст или пути архива. Подробности — [docs/Architecture.md](docs/Architecture.md).

Новые записи микрофона сохраняются в моно PCM16 / 16 кГц (около 115 МБ/час) независимыми 10-секундными CAF-фрагментами, затем потоково собирается в `source/original.caf`. Ресэмплинг непрерывен на протяжении сессии; сборка сохраняет PCM16. Уже сохранённые записи и импортируемые файлы не перекодируются. Подробности и проверки — [CapturePCM16](docs/CapturePCM16.md). При сбое перезапустите приложение и нажмите «Продолжить». Восстанавливаются только завершённые фрагменты; текущий фрагмент может быть утрачен. Граница потерь при реальном принудительном завершении требует отдельной проверки, не гарантирует сохранность при отключении питания.

После аварии модели сами не запускаются. «Продолжить» использует подходящие контрольные точки, с проверкой исходного SHA, ревизий и версии pipeline. Диаризация повторяется целиком, ASR заново не нужен. При повторной обработке прежний успешный результат показывается до готовности нового. При ошибке диаризации остаётся промежуточный текст, при ошибке LLM — готовая расшифровка. Удаление записи требует подтверждения и затрагивает только её каталог; экспортированные файлы и внешние оригиналы остаются.

## Проверки разработчика

```sh
swift test -c release -j 4
python3 -m unittest discover -s scripts/tests -v  # bootstrap и сборка FFmpeg: локальные фикстуры без весов и сети
python3 scripts/format_checks.py         # декодирование, включая AAC ADTS; нужны Assets/tools и локальные аудиофикстуры
python3 scripts/download_models.py       # только bootstrap разработчика, те же SHA-256
python3 scripts/download_models.py --model asr-small --model summary-4b --model diarization
python3 scripts/smoke.py /path/to/audio.wav --worker .build/out/Products/Release/LocalScribeWorker
python3 scripts/fault_checks.py TestResults/smoke/RECORDING_UUID --worker .build/out/Products/Release/LocalScribeWorker
bash scripts/package_source.sh
```

Bootstrap проверяет размеры и SHA-256 файлов даже в существующих папках моделей. Повреждённый комплект восстанавливается через `.partial` и заменяется только после проверки всего набора; корректные файлы `.partial` используются повторно. `catalog.json` публикуется после успешной установки всех выбранных профилей; при ошибке скрипт завершается с ненулевым кодом.

Воспроизводится состав и процедура сборки; побайтовая идентичность бинарников между разными toolchain/подписями не заявляется.

В некоторых версиях SwiftPM путь к продуктам отличается: получите его через `swift build -c release --show-bin-path` и передайте `--worker`. Probe запускает реальные модели; результат помещается в `TestResults`, а не в пользовательский архив. SDK stderr по умолчанию отбрасывается; `--trace` предназначен только для явно выбранного технического аудио и сохраняет модельную диагностику локально. Запрещено считать синтетическую речь тестом WER/DER или заменить ею приёмку на настоящих встречах.

Для разработческой проверки подписанного sandbox используются `open -n dist/LocalScribe.app --args --self-check --self-check-download` и, при наличии локальных моделей/технического аудио, `bash scripts/signed_probe.sh`. Второй скрипт создаёт отдельную диагностическую .app с копиями публичных весов; она не входит в поставку. Отчёт находится в Application Support её отдельного контейнера. Синтетический звук не попадает в пользовательский архив.

Установленную сборку нужно отдельно проверить после перезагрузки с отключённой сетью, на 3 часах реальной речи и в условиях давления памяти. Встроенное декодирование согласованных кодеков уже проверено, но GUI-импорт, запись микрофона и качество на эталонных встречах требуют отдельной приёмки. Матрица — в `docs/Acceptance.md`, пошаговый оставшийся прогон — в `docs/MacAcceptance.md`, измеренные факты — в `docs/Measurements.json`.
