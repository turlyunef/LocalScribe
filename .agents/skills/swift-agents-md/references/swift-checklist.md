# Swift-чеклист

Пройди все строки. Состояния в рабочем отчёте: подтверждено (путь/строка или
вывод команды), не применимо (почему), неизвестно (какого свидетельства нет).
Ищи локальные решения; не подставляй рекомендации Apple вместо практики проекта.

| Проверка | Что установить и какое правило вывести |
| --- | --- |
| Тип проекта | Найди .xcodeproj/.xcworkspace, Package.swift, XcodeGen project.yml, Tuist Project.swift/Tuist.swift, Podfile/Cartfile, Bazel. В монорепозитории перечисли разные способы сборки и рабочие каталоги. |
| Targets и schemes | Сопоставь shared .xcscheme, manifest и успешный xcodebuild -list. Для основных схем проверь destinations и build settings. Не делай вывод о доступной схеме только из имени target. |
| Платформы и версии | Разделяй SDK, минимальную ОС, установленный Swift, swift-tools-version и language mode. Проверь .xcode-version, .swift-version, .tool-versions, xcconfig, SWIFT_VERSION и SWIFT_STRICT_CONCURRENCY; условные настройки могут отличаться по target/configuration. |
| Генерируемый .pbxproj | Если project.yml/Project.swift действительно генерирует этот проект, правь источник генерации, а не .pbxproj: следующая генерация затрёт ручную правку. Наличие XcodeGen где-то в монорепозитории не делает все проекты генерируемыми. |
| Synchronized folders | Найди PBXFileSystemSynchronizedRootGroup и его привязку к target/исключениям. Для таких папок обычно не нужно добавлять файл в .pbxproj вручную; для остальных групп следуй устройству проекта. Не выводи это только из версии Xcode. |
| Lockfiles, generated, кэши | Проверь git ls-files/check-ignore и CI для Package.resolved, *.generated.swift, DerivedData, SwiftGen/R.swift. Следуй реальной политике: Package.resolved нередко отслеживается. Генерируемые исходники меняй через установленный генератор; не вводи общий запрет коммита lockfile. |
| Конфигурация и подпись | Info.plist, entitlements, signing, provisioning и xcconfig с секретами меняй только по явному запросу: они влияют на возможности/распространение приложения. Уже данный явный запрос достаточен; не требуй повторного подтверждения. Содержимое секретов в документ не копируй. |
| Core Data | Найди .xcdatamodeld, текущую версию модели и процесс миграций. Изменения схемы проводи через новую версию модели и миграцию: изменение выпущенной модели может сделать сохранённые данные нечитаемыми. Если Core Data нет — не добавляй этот запрет. |
| Concurrency | Сопоставь language mode, strict concurrency/default actor isolation и код: async/await, actors, Combine, @MainActor, Sendable, nonisolated. Укажи образец границ изоляции. Не предлагай @unchecked Sendable, nonisolated(unsafe) или отключение проверок как стандартный ремонт. |
| UI и навигация | Проверь SwiftUI/UIKit/AppKit и смешанные экраны, Objective-C и SWIFT_OBJC_BRIDGING_HEADER. Для новых View выясни по существующему коду, требуются ли #Preview, accessibility identifiers/labels, String Catalogs или иной механизм локализации. |
| Архитектура и DI | Найди композицию зависимостей, маршрутизацию и направление зависимостей модулей. Приведи файл-образец и границы слоя; не выдавай предполагаемое название архитектуры за установленное. |
| Сеть/хранилище/ошибки | Подтверди реализацию сети и SwiftData/Core Data/GRDB/другого хранения, правила ошибок и логирования по нескольким файлам. Укажи только отличия и ограничения, нужные для нового кода. |
| Тесты | XCTest, Swift Testing (@Test), snapshot/UI, mock/fake: названия реальных suite/test, расположение fixtures и причины известных ограничений. Проверяй фильтр одного теста: zero tests не означает успешную проверку. |
| Linux | Для SwiftPM выясни поддержку Linux по CI, документации и зависимостям. При поддержке укажи принятые #if canImport/#if os и команду Linux CI. Не объявляй пакет переносимым только из-за Package.swift. |
| Макросы и плагины | Найди macro/plugin targets, toolchain/SwiftSyntax и документированное доверие. Флаги пропуска validation на CI записывай только если они реально есть; не добавляй и не запускай обход trust ради проверки. Отсутствие доверия — причина `(не проверено)`. |
| Ресурсы и кодогенерация | Проверь .xcstrings, .xcassets, bundle/module доступ, SwiftGen/R.swift и другие генераторы; отдели входные файлы от результатов, укажи настоящую команду и момент её запуска. |
| Вывод xcodebuild | xcbeautify/xcpretty допустимы только если уже используются/предусмотрены проектом. Установи exit code самой сборки, иначе formatter может скрыть падение. |
| Зависимости | Способ добавления/фиксации версий устанавливай по manifest, lockfiles, CI и CONTRIBUTING. Если причины pin неизвестны, не придумывай их. Обновление пакетов не входит в подготовку AGENTS.md. |
| Git/PR/ловушки | Сопоставь ~30 коммитов, правила веток и PR template. Медленные/нестабильные тесты, симуляторные ограничения и workaround должны иметь источник; случайный сбой одного запуска не доказывает flaky-тест. |
